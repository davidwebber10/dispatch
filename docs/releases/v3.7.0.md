# Dispatch v3.7.0: sign in your phone with a code or a QR code

## The change

- **Settings → Access.** A new settings section, on desktop and on mobile. Tap **Make a code**
  and Dispatch shows a sign-in code like `ABCD-EFGH` and a QR code. The code works once and
  lasts 5 minutes. A field holds the address the phone will use; it goes into the QR code.
- **A splash page on the other device.** A phone that is not signed in now sees the Dispatch
  mark, two steps, and an **Enter a code** button, instead of a bare token box. Scan the QR
  code with the phone's camera and open the link: the phone signs in and the app opens. Or
  tap **Enter a code** and type the code. The access token still works in the same box.
- **The token stays home.** The long token is never sent to the browser. The only secret that
  leaves the daemon is the short, one-time code. `dispatch access` and `dispatch access
  rotate` are unchanged.

## What was wrong

Since v3.4.0 a phone outside Tailscale sees a sign-in page, and the only way in was to paste
the 43-character token from `dispatch access`. That command refuses to run inside a Dispatch
thread, and on many machines `dispatch` is not on the `PATH` (use `./bin/dispatch` from the
repository folder). So the phone was locked out.

## Under the hood

- `POST /api/access/pair-code` (owner only; 404 on a hosted box) issues a code. One code is
  live at a time; a new one replaces the old. Compared in constant time, consumed on first use.
- `POST /api/access/login` takes `{ code }` as well as `{ token }`. A wrong code is `bad_code`
  and spends the same 10-tries-a-minute budget as a wrong token. The sign-in page also
  handles a `#code=` link, next to the existing `#access=` link.
- The page keeps its strict Content-Security-Policy: inline mark, system font, script by hash.
- New tests: the code module, code login over HTTP, the splash page, the Access section with
  its QR code and countdown. `docs/network-access.md` describes the new flow.
- This is the first slice of the Phase 2 pairing design (`docs/superpowers/specs/2026-10-22-network-exposure-design.md`, 8.1). Paired-device lists and the wizard QR code are still to come.

## Known items

- A phone that signs in through a tunnel cannot install Dispatch as an app yet: the browser
  fetches `manifest.webmanifest` without the sign-in cookie and gets 401. Not new in this release.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
