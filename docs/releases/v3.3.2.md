# Dispatch v3.3.2: doc links work in every view

## The change

- **Doc links open the doc viewer everywhere (#100).** v3.3.0 fixed doc links in Chat only. In
  the Control Plane (overseer) and a few other views, a link to a `.md` or `.txt` file was still
  treated as a web address. Clicking it loaded `localhost:3456/Users/...`, which reopened the
  same thread. All structured views now share one link rule:
  - `.md`, `.markdown` and `.txt` links open in the doc viewer, including full paths, relative
    paths, and paths with a line number such as `file.md:12`.
  - Web and `mailto:` links open in a new tab.
  - Links that point back to Dispatch's own host (`localhost:3456/Users/...md`) open in the doc
    viewer if the file is inside a project. Links to other Tailscale or network hosts open in a
    new tab.
  - `javascript:`, `file:///` and `../` escapes do nothing.
  - Views covered: Control Plane stream, ledger source panel and chips, Chat replies and notes,
    file tabs, web previews, release notes. Relative links in the Control Plane open from the
    project folder.
- **CLI threads:** links the agent marks as real links (OSC 8) now follow the same rule.

Known limits:
- In CLI threads, plain-text file paths that aren't marked as links are still not clickable.
- Not yet tested on the iPhone or on a real terminal.
- Web preview text is now slightly larger and brighter than before.
- On the phone, the same CLI thread open in two places can open two viewers.
- The folder-swap race from #94 is unchanged.

## Updating

Web app only. Run `dispatch update`, then reload the app.
