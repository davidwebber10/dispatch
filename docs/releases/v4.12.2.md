# Dispatch v4.12.2: an update no longer changes your default Claude account

## The change

- **A saved Claude sign-in never becomes the default account by itself.** Dispatch still lists it in Settings → Accounts as "Dispatch login", but new threads and scheduled jobs keep the account they used before.
- **Removing "Dispatch login" now sticks.** Before, it came back at the next restart.
- **If the removal cannot finish, Dispatch says so** and keeps the account, instead of reporting success.

## What was wrong

A Claude sign-in made inside Dispatch (for example from the Chat sign-in card) was kept in an old single-login file. At the next restart, Dispatch turned that file into the account "Dispatch login" and made it the default. Every new thread and every scheduled job then ran on that login without a notice.

That login is a token login. It has no claude.ai connectors, so threads and jobs that read mail, calendar or chat lost those tools.

## Check your install

Open Settings → Accounts. If "Dispatch login" is the default and you did not choose it, set the default back to the login of your computer. This release cannot tell an old silent change from your own choice, so it does not change the default for you.

## Limits

- If your computer's Claude login is signed out and you sign in from a card inside Dispatch, the new "Dispatch login" is not the default. Set it as the default in Settings → Accounts, or sign in with `claude` in a terminal.
- Chat, thread titles and the usage check can still use the old saved sign-in while it exists. A later release gives every part of Dispatch the account you chose.

## Updating

Needs a daemon update: run `dispatch update`, then reload the app.
