# Dispatch v4.14.0: a Claude account can keep its claude.ai connectors

## The change

- **"Add account" for Claude has a full sign-in.** Settings → Accounts → Add account now offers two kinds. "Full sign-in" signs the account in with Claude Code's own login, in a folder of its own. A thread on that account gets the claude.ai connectors of that account: mail, calendar, chat and the others. "Model only" is the sign-in that Dispatch offered until now.
- **The page of such an account shows its sign-in state.** When the account is signed out, the page offers the sign-in again. Removing the account signs it out first.
- **The Chat sign-in card offers a saved sign-in that you already have.** When a Chat turn fails with no login, and your default account is the login of your computer, one click makes the saved sign-in the default and sends the message again.
- **A new thread no longer shows the conversation of another thread.** It could happen in a new project, when two threads were made less than a minute apart.
- **A failed Claude sign-in says the reason that Claude Code gives.** Newer versions of Claude Code changed their words, and Dispatch then said "Claude did not accept that code" for every failure.

## Why

An account that you added before this release has a token from `claude setup-token`. That token runs the model and nothing more: Claude Code cannot fetch the claude.ai connectors with it. So a thread on an added account had no mail, calendar or chat, although the same account shows them on claude.ai.

A full sign-in is the login that `claude` makes in a terminal. Dispatch holds no token for it. Claude Code keeps the login itself, on a Mac in the keychain.

## If you have an account with no connectors

Open Settings → Accounts. Add the account again and keep "Full sign-in". The code from the Claude page has a `#` in the middle: paste all of it. Then remove the old account. This release does not change an account that you have.

## Limits

- A server that you added to Claude Code yourself at user scope is not in a full sign-in account. Integrations that Dispatch gives a thread still come.
- When your own `CLAUDE.md` in the home folder imports another file, Claude Code asks once for each project, in the first CLI thread of the account there, whether it may load external imports. A Pretty thread shows no question.
- The window for a new thread still adds an account as "Model only". Use the Accounts page for a full sign-in.
- A thread whose stored session was cleared can still lose its transcript to a thread made in the same minute, in a project with one transcript.

## Hosted boxes

A hosted box already signs every account in this way and does not change. One part reaches a box when its image takes a newer Claude Code: the reason of a failed sign-in.

## Updating

Needs a daemon update: run `dispatch update`, then reload the app.
