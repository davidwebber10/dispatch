# Dispatch v3.8.2: attach PDFs and text files in Chat

## The change

- **Chat takes documents now.** The paperclip in Chat, on a phone and on desktop, offers PDF,
  TXT, MD, CSV and JSON files next to images. A picked, dropped or pasted document shows as a
  chip with its name. Tap × to remove it. A document can be up to 20 MB.
- **The model reads them.** Dispatch saves the file and tells Chat its path. Chat reads it with
  its Read tool, which reads PDFs. The sent message shows the file as a chip that opens it.
- **No more silent drops.** A file Chat cannot take is named in a notice, with the list of
  types it does take.

## What was wrong

Chat accepted four image types and nothing else. On a phone the file picker hid PDFs, a
pasted PDF was ignored without a word, and the daemon refused any other type. Thread chats
were not affected: they upload any file to the project inbox.

## Under the hood

- `POST /api/endless/send` takes `files: [{ name, media_type, data }]` next to `images`.
  The daemon saves each file in Chat's media folder under a safe form of its name and adds
  the path to the message's media list. The turn names non-image media in one text block.
- A phone often reports no type for a file; the extension is the fallback, but a real type
  always wins over the name.
- New tests: the service's file saving and names, the turn's attached-files block, the
  composer's pick, paste, chip, notice and send paths.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
