# Dispatch v3.1.5: threads start again with Dispatch's Claude login, and no Automations tab on mobile

## The change

- **Threads no longer refuse to start when Dispatch holds your Claude login.** If you signed
  in with the "Log in to Claude" box, new threads now start even when the Claude CLI's own
  login on the computer has expired. Before, they stopped with "claude-code CLI is not signed
  in on this server".
- **No Automations tab on mobile.** The bottom tab bar on a phone now shows Projects, Chat,
  Pinned, Analytics and Settings. Automations is still on desktop.

## What was wrong

Before starting a thread, Dispatch asks the Claude CLI whether it is signed in. It asked
without the saved token that Dispatch gives every thread it starts. So when the CLI's own
login expired, the check said "signed out" and blocked the thread, even though the thread
would have run fine with Dispatch's token. The check now runs with the same settings a
thread gets, so it sees the saved token.

## Under the hood

- The sign-in check reruns as soon as those settings change (for example, right after you
  log in), so it never reuses an old "signed out" answer.
- New test: the check sees the saved token and counts it as signed in.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update`, then reload the app.
