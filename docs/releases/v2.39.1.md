# Dispatch v2.39.1 — roles report, they do not delegate

Scheduled roles now stay inside their own run. (PR #48.)

## What was wrong

- **A role could hand its work to an agent with no rules.** A role run had the full set of
  Dispatch tools. It could call `spawn_agent` or `queue_agent`, and the new agent ran with no
  role policy at all. That agent could do what every role authority denies, for example
  `gh pr merge`, a push to `main`, or a release. A role could also steer a live thread with
  `message_thread`, `message_agent`, or `answer_agent`.
- **An `observe` role could change data through other MCP servers**, for example secrets,
  email, tickets, or a store.
- **Every role run woke the project's coordinator.** A role run's completion, `needs_you`, or
  question went to the Control Plane, started it again if it was stopped, and asked it to
  "spawn a follow-up" or answer the role's question. This happened on every run in a project
  with a coordinator.
- **The "no native subagents" rule for roles did nothing.** Claude approves `Agent`, `Task`,
  and `Workflow` on its own, so the role policy never saw those calls.

## The change

- A role run can use only the read, report, and watch tools of Dispatch: `list_threads`,
  `read_thread`, `list_agents`, `read_agent`, `list_missions`, `report_status`, `post_image`,
  `watch_thread`, `unwatch_thread`, `list_watches`. Dispatch denies all other Dispatch tools,
  including any tool added later.
- A role run no longer gets the delegation tools or `Agent` / `Task` / `Workflow`. Claude
  removes them when the run starts.
- An `observe` role cannot call a tool from any other MCP server. `stage` and `stage-deploy`
  roles keep your other MCP servers, as before.
- A role run never notifies the coordinator. Its report goes to its log and the morning
  digest. A question it asks waits for you.
- `docs/roles.md` now states the limit plainly: the role policy guards against drift, but it
  is not a sandbox. GitHub branch protection stays the real wall.

## Updating

Daemon only. Run `dispatch update`; its restart applies the change.
