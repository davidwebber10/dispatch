# Dispatch v2.8.15 — A thread's findings stop hiding inside report_status

## The problem

A thread would finish its work, call `report_status` with its findings and its
question tucked into the tool arguments, and leave a visible reply of just "waiting
on your feedback." The important part was there — but buried inside a tool call.

- In **Pretty** mode, every tool except `AskUserQuestion` rendered as a collapsed
  "Wrench" block, so the summary/ask/blocker were hidden until you expanded it.
- In **PTY** mode (real Claude Code in a terminal), Claude Code's own TUI collapses
  tool calls — you'd have to press **Ctrl+O** to see what the thread actually said.

Either way, reading the thread directly, you couldn't see what it wanted.

## The fix — two levers, one per surface

**Pretty (render).** `report_status` now renders **inline and visible** instead of a
collapsed block: an amber **"⏸ Waiting on you" / "Blocked"** card carrying the
summary and the question/blocker verbatim (a finished turn stays a muted one-line
summary). Because this is a rendering change, it fixes **existing** threads too —
not only ones started after the update.

**PTY (prompt).** Dispatch can't reformat Claude Code's own terminal UI, so the only
lever there is the system prompt. It now says, explicitly, that a tool call's
arguments are collapsed out of sight (Ctrl+O to expand), so anything a thread puts
*only* inside `report_status` is invisible — findings, answer, and any question
**always go in the reply text**; `summary`/`ask` are a copy for the board, never the
place to say something you didn't also write in your reply. This affects threads
started with the new prompt (a running thread keeps the prompt it booted with, so
start a fresh thread to feel it).

## Why both

The status tool still does its job — it captures the state for the board and alerts.
What changed is that the thread's *content* no longer lives only there: Pretty
surfaces it, and PTY threads are told to say it out loud. Verified with 22 new
unit/component tests plus the strengthened prompt regression.
