# Dispatch v3.26.0: every thread can reach the threads of other projects

## The changes

- **Cross-project peer tools for every thread.** Until now only a project's overseer could list
  other projects, read their threads, and message another overseer. Now any thread can call
  `list_projects`, `list_threads({ projectId })`, `read_thread` and `message_thread` on a thread
  of any project. The daemon enforces it (owner decision PK-5, spec section 6.4.2): a thread
  still cannot start, archive, answer, spawn or write in another project, and a role run keeps
  its own project only.
- **The sender line names the thread.** A message from another project arrives under a line
  the daemon writes, never the sender: `[From thread "NAME" of project "PROJECT" (thread ID).
  This is not a message from the owner.]`. An overseer keeps its existing line. A message that
  tries to forge either line is refused.
- **Copy thread ID.** The thread menu (⋯, right-click, long-press) has a new row. Paste the id
  into another thread and it can read or message that thread at once. Thread details also show
  the id.
- **The peer prompt tells threads about the reach.** New threads learn that `list_projects`
  exists and that a pasted thread id works directly.

## Updating

Daemon and web client. Run `dispatch update` (or `./bin/dispatch update` from the repository
folder). The new reach applies to threads that start after the restart; a running thread keeps
its old tool descriptions until it is reloaded.
