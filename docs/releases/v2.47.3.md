# Dispatch v2.47.3 — Codex threads stay at the latest output

Codex terminal threads no longer jump far up when you submit a prompt or return to the
thread. (PR #73.)

## The change

When Codex rewrites its history after a terminal resize, the thread view now stays at the
latest output if you were already there. If you scroll yourself while Codex rewrites (wheel,
trackpad, scrollbar, touch, or Shift+PageUp), the view stops following at once. If you were
scrolled up reading, the view does not move.

## What was wrong

Since v2.47.1, Codex terminal threads run in inline mode, so that you can scroll back. In
that mode, Codex answers every terminal resize by clearing the screen and the scrollback and
writing about 1000 lines of its history again. A submit, the end of a turn, a return to the
thread, and a window resize all resize the terminal. The browser took the scrollback clear
for your own scroll, so the view stopped following and stayed 1000 to 3000 lines above the
latest output, with "Scroll to latest" showing.

## Updating

Web app only. Run `dispatch update`, then reload the page. Codex still rewrites its history
after a resize; only the jump is gone.
