# Dispatch v2.27.0 — Stop a running turn from the composer

## The change

Send a message in Pretty mode and the composer key now turns into a **Stop** button while the
turn runs. Press it and the turn ends — the thread stays alive and you keep the conversation.

The key is dual-purpose, and typing always wins:

| Thread | Composer | Key |
| --- | --- | --- |
| Working | empty | **Stop** |
| Working | you've typed something (or staged an image) | **Send** |
| Idle | empty | Send, disabled |
| Idle | has content | **Send** |

So a running turn gives you a brake, but the moment you start typing a follow-up the key goes
back to Send — a mid-turn message still goes out as its own queued turn, exactly as before.

## What Stop actually does

It sends the **graceful interrupt** the daemon already exposes: Claude Code gets the
stream-json `interrupt` control on stdin, Codex gets `turn/interrupt`. That ends the current
turn and **leaves the thread running** — it is deliberately *not* the "Stop" that kills an
agent's process (the Overseer's own kill control), so nothing is lost and you can carry
straight on in the same conversation.

Stop appears only while a turn is in flight. A native compaction is left alone to finish —
interrupting one mid-way risks a mess — so during a compact the key stays a disabled Send.

## Under the hood

- `ChatView`'s composer key gains a `stopMode = busy && !canSend` branch: `onClick`, `title`,
  icon (a filled Phosphor `Stop` square) and colors all switch on it.
- Stop is deliberately red-tinted rather than reusing the disabled key's grey, so an *active*
  brake can never read as a dead Send button.
- No backend work: the `POST /api/terminals/:id/interrupt` route, the per-provider manager
  implementations, and the `api.interrupt()` client method all already existed.
- Four new tests in `ChatView.test.tsx` pin the state machine, including a guard that the
  composer's Stop calls `interrupt` and never `stopTerminal` (which would kill the thread).

Web-only — a browser refresh (or the auto-update) picks it up; no daemon restart needed.
