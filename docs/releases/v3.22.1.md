# Dispatch v3.22.1: file chips for every file type

## The change

- **File chips work for any file, not only `.md` and `.txt`.** Chips in Chat replies, thread
  replies, report cards and Started cards now open:
  - `.md` `.markdown` `.txt`: the doc viewer, as before.
  - Code and text data (`.py` `.ts` `.json` `.sql` `.sh` `.yml` `.csv` `.svg` ...) and images: a
    file tab. From Chat, the app switches to the Threads view on that tab.
  - Other binary files (`.xlsx` `.parquet` `.pdf` `.zip` `.docx` ...): a download from the
    project. An alert shows if it fails.
- **Fewer false chips.** URLs, domains, emails, version numbers, `e.g.`, `Node.js` and code
  calls like `res.json(data)` are not chipped. Windows paths (`C:\...`, UNC) get no chip; WSL
  `/mnt/c/...` paths chip only inside a registered project.
- **Right project.** A relative path resolves against the message's own project first
  (`docs/`, `web/`, `./` stay put). A path that starts with another project's folder name
  (`sandbox/team-requests/board.md`) opens in that project.

## Security

- File reads, downloads and image loads now open files without following a symlink swapped
  in mid-request, and refuse (403) any path that lands outside the project.
- Known limit on macOS: a coordinated swap of a parent folder during a read is narrowed, not
  fully closed.

## Known gaps

- Markdown links like `[x](sandbox/a.md)` still use the message's project.
- Chips never check the file exists; a missing binary shows a download-failed alert.
- Not tested on the phone.

## Updating

Server and web client. Run `dispatch update` (or `./bin/dispatch update` from the repository
folder), then reload the app.
