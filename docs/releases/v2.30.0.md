# Dispatch v2.30.0 — archived threads, back in reach

## The change

Each project card in the sidebar now has a quiet **ARCHIVED** section below FILES. It
appears only when the project has archived threads. Expand it to see them, newest first,
ten at a time. Click the restore arrow on a row to bring the thread back: it rejoins the
thread list and resumes the same conversation it had when it archived.

The section stays in sync on its own. When a thread hits its auto-archive timer, or when
you archive or restore one from another device, the list updates in place.

## What was wrong

Archiving has always been a soft delete, and the daemon could already restore a thread
onto its original conversation. But no general UI listed archived threads. A thread that
hit the auto-archive timer simply vanished from the sidebar, and the only way back was
the raw API.

## Under the hood

- New `ArchivedSection` component; `SectionHeader` and `ShowMoreRow` moved to a shared
  `sectionParts.tsx`.
- Dispatch-managed rows (the coordinator and typed agents) stay hidden, matching the
  live thread list.
- Race guards: an in-flight lock on restore (a double click sends one request), a
  stale-response counter on overlapping fetches, and a retry row on a failed fetch.
- 13 new tests; web suite 1088/1088.

## Updating

**Web-only** — after `dispatch update`, a browser refresh is enough; nothing in core
changed.
