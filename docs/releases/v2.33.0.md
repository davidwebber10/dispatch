# Dispatch v2.33.0 — CLI threads stop swallowing responses

## The change

Three fixes for the long-standing "the agent finished but I can't see the full response"
report, all aimed at the CLI (PTY) transport:

- **New claude threads default to Pretty.** The structured chat renders every turn
  completely — no byte replays, no TUI quirks. A saved Settings → Harnesses preference
  still wins, and codex keeps its own CLI default.
- **CLI threads nudge you toward Pretty.** A one-time dismissible bar with a direct
  "Switch to Pretty" button, gated exactly like the transport toggle (session captured,
  no turn in flight).
- **The latest declared outcome shows above the CLI terminal.** Agents put their real
  findings in `report_status` arguments, and the TUI collapses tool arguments to one
  truncated line. The new card renders the declared DONE / BLOCKED / NEEDS YOU outcome —
  summary and blocker — through the same card the Pretty chat uses. It hides mid-turn
  and refreshes itself when the turn settles.
- **The terminal replay never shows width-scrambled garbage again.** Reopening a CLI
  thread after another device (phone vs desktop) had resized the shared pty rendered the
  scrollback as shredded one-character columns. A width-changing resize now evicts the
  unreplayable bytes, and the client declares its fitted size on the socket URL so the
  server resizes the pty *before* it replays. Trade-off, made deliberately: after a
  cross-width device switch you get a clean current screen with no old scrollback,
  rather than scrollback-shaped noise.

## What was wrong

Every new claude thread defaulted to the CLI transport, and that view lost content three
ways: raw byte replays rewrap into noise at a different width, the replay window is
bounded, and a respawned TUI prints only a resume stub. On top of that, agents bury
their substance in `report_status` arguments the TUI collapses. (An earlier theory
blamed the chat renderer's uuid handling; a captured real stream disproved it.)

## Under the hood

- `lib/harnesses.ts`: per-harness `defaultMode` + `defaultModeFor()`; claude → `pretty`.
- New `CliPrettyHint` and `CliStatusCard` components, mounted by `TabHost` for
  non-structured AI threads only.
- `RingBuffer.trimToNow()` in core; `PTYManager.resize` calls it on width changes;
  `ws/terminal.ts` honors declared `cols`/`rows` URL params before replaying;
  `terminal-socket.ts` sends them, re-read on every reconnect.
- Tests: 21 new web tests, 9 new core tests. Web suite 1124, core suite 1610.

## Updating

**Core + web** — run `dispatch update`, then refresh the browser. The daemon must
restart for the pty replay fix; `dispatch update` does that.
