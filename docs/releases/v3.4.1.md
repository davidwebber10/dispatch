# Dispatch v3.4.1: security hardening

A batch of smaller security fixes from the October security review (#103). Nothing to set up.

## What you will notice

- **Images from other websites in replies wait for a click.** A "Load image from HOST" button
  shows in their place. Each website is asked about separately. Images from your own computer
  still show right away.
- **`dispatch update` and the in-app Update now install the latest release**, not the newest
  unreleased commit on `main`. A checkout whose remote has no release tag gets a clear error.
- **Settings lists secret names only.** A secret's value is fetched when you click reveal or copy.
- **Uploads over 100 MB are refused.** A cancelled or failed upload leaves no file behind and
  never overwrites the destination.
- **The editor opens regular files up to 5 MB.** Larger files and device files show an error
  instead of hanging.
- **A shell tab cannot watch another thread.**

## Other changes

- The app sends a Content-Security-Policy: scripts and connections only from Dispatch itself,
  no framing, no plugins. The sign-in page still works.
- Delete and rename refuse the project folder itself.
- Replies no longer render SVG or MathML, and the sanitizer drops styles, forms and media sources.
- Control characters are removed from text pasted into CLI threads and from watch notes.
- Per-thread MCP config files are private (`0600`) and cleaned up when their thread is not running.
- Copying an image from chat works under the new policy (`data:` and `blob:` images included).
- New `docs/security.md`, plus README notes: one Dispatch per person, never share the token,
  agents run with your rights, telemetry and its off switch.

## Known items

- Not yet covered: a read-only Doppler token for threads, and per-thread API keys (designed
  separately).
- The image copy fixes and cancelled-upload handling are covered by automated tests only.

## Updating

Run `dispatch update`, then reload the app.
