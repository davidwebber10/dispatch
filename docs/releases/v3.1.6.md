# Dispatch v3.1.6 — Claude threads start again when the Claude CLI is signed in

## The change

- **New Claude threads start again on macOS.** In 3.1.5, Dispatch could say "claude-code CLI
  is not signed in on this server" and offer a "Sign in — Claude Code" thread, even though
  the Claude CLI was signed in. Threads that were already running kept working. That false
  "signed out" answer is gone.
- If you opened a "Sign in — Claude Code" thread because of this, you can close it. You do
  not need to sign in again.

## What was wrong

Before it starts a thread, Dispatch asks the Claude CLI if it is signed in. In 3.1.5 that
check ran with only the extra settings that Dispatch adds for threads, not the full
environment of the computer. The missing piece was `USER`. On macOS the Claude CLI finds its
saved login in the keychain by that name, so without it the CLI answered "not signed in".
The check now uses the full environment with Dispatch's settings on top, the same as a
thread gets.

## Under the hood

- New test: the sign-in check keeps the daemon's own environment under the thread settings.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update`, then reload the app.
