# Dispatch v4.4.2 — adding a Claude account works again

## The change

- **One sign-in link, and it shows a code.** When you add a Claude account, no extra browser tab
  opens. Use **Open the Claude login page**, approve, and paste the code that Claude shows.
- **The new account appears at once.** The login finishes only after Dispatch has stored the
  account, so Settings shows it right away. If the save fails, the login says so.
- **Each login keeps its own account.** Starting a login for a different account replaces the one
  that is waiting, so a sign-in cannot land on the wrong account.
- **The code box knows when a login has ended.** It closes when the login finishes. If the login
  has stopped, it says "This login ended. Start it again."

## What was wrong

`claude setup-token` makes two links. It opened one in a browser by itself, and that link shows
"ready to start building" and no code. Approving it finished the login in a way that Dispatch did
not read, so nothing was saved, and a code from the other link then got "no login in progress".

## Known limits

- A login token that the terminal splits in two at the exact moment of a code can make the login
  fail or save an incomplete token. Sign in to that account again if this happens.
- A real sign-in on Windows was not tested.

## Updating

Needs a daemon rebuild and restart: run `dispatch update`, then reload the app. Running threads
are not affected by the login change.
