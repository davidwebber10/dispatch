# Dispatch v2.14.1 — it notices when a CLI signs out

## The change

Dispatch now asks each agent CLI whether it is signed in, rather than looking for its
credential file. So a session that expires is spotted, and the Sign in panel appears before
you start a thread that would dead-end.

## What was wrong

The credential file only disappears on an explicit logout. A token that merely **expires**
leaves the file exactly where it was — so detection reported "signed in" right up until the
thread stopped at a login screen. Expiry is the common case.

Each CLI can answer properly, and now does:

| CLI | Probe |
| --- | --- |
| Claude Code | `claude auth status --json` — machine-readable |
| Codex | `codex login status` |
| Grok | `grok models`, which says plainly when there is no account |

Only a definitive yes or no from the CLI overrides the file. A probe that cannot run, or
output that is not recognised, defers to the file instead — so a CLI that rewords its output
in a future version degrades to the old behaviour rather than confidently lying.

## Under the hood

Answers are cached for 30 seconds, so opening the New Thread modal does not spawn three
status processes every time. `?fresh=1` bypasses the cache and is used in the two places a
stale answer would be wrong: the Setup wizard's **Re-check** button, pressed right after you
sign in, and the install action, which has just changed what is on disk.

Two latent test bugs surfaced and were fixed: the signed-in cache is keyed by provider name
alone, so a verdict leaked between tests; and several install tests depended on whether the
developer's own machine had a CLI installed, which inverted once Grok was.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`) — detection is in core.
