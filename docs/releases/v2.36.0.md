# Dispatch v2.36.0 — Scheduled roles: sessions are cattle, roles are pets

Recurring work now runs as **roles**: durable, refinable definitions at
`~/.dispatch/roles/<name>/` (a `role.md` brief you edit, a curated `memory.md`, an
append-only `log.jsonl`) whose scheduled incarnations are **fresh, short-lived
structured agents**. Every run inherits the role's full accumulated refinement by
reading files — never by resuming a conversation — so context rot (turns, tokens,
or wall clock) is structurally impossible.

Design: `docs/superpowers/specs/2026-09-02-scheduled-roles-design.md`.
Operator guide: `docs/roles.md`. (PRs #40/#41/#42.)

## Highlights

- **Definitions travel, activation doesn't.** `~/.dispatch/roles` can be its own
  git repo for backup/sharing; enabling is always a deliberate per-machine act
  (`dispatch roles list / enable / disable`). Discovery never starts anything.
- **The lifecycle.** Cron fires (the existing scheduler) → a fresh typed agent
  spawns with the brief + memory + last run reports + a current-time freshness
  instruction → one bounded stint (default 45-min wall cap) → a structured report
  appends to the role's log and the runner archives.
- **Daemon supervision, no agent watchdogs.** Retry once per fire (hard cap of 2
  attempts), crash-exit finalization, and 2 consecutive failed nights auto-disable
  the role with a push notification.
- **Per-role authority at the membrane.** `observe` / `stage` / `stage-deploy`:
  runners may stage branches and PRs, but merges, deploys, releases, production
  workflows, and protected-branch pushes are denied at the tool layer — hardened
  through five adversarial review rounds (chained commands, quoted-arg smuggling,
  colon-refspecs, canonical refs, git dst-disambiguation, ambiguous HEAD targets),
  with bypasses verified closed against a real git remote. Main and production
  stay explicit-human-approval-only; GitHub branch protection remains the backstop.
- **Morning digest.** A shipped global role reads every role's overnight reports
  plus project statuses and writes one cross-project summary to a pinned
  `digest.md` file tab in the Operations project, with a push headline — leading
  with failures and staged-work-awaiting-review.
- **Four seed roles** ship as examples in `docs/examples/roles/`:
  rollup-nightly-check, legacy-repo-chores, ci-pr-babysitter, morning-digest.

## Updating

Daemon-side: `dispatch update` (restarts the daemon) is required before the roles
machinery exists on a machine. Then copy the example roles you want into
`~/.dispatch/roles/` and run `dispatch roles enable <name>`. v1 runners are
claude-code only.
