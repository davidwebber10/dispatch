# Dispatch v2.46.1 — WSL installation and reliable updates

## The change

- **Agent installation without sudo.** Claude Code, Codex, and OpenCode install into Dispatch's user-owned tools directory. They are detected immediately and available in new threads, even when system Node is installed under a root-owned directory.
- **Updates finish with the browser open.** Shutdown now disconnects browser WebSockets so the old daemon can exit and WSL can start the replacement. Previously, an open browser could make restart time out and leave Dispatch unavailable.
- **Useful update failures.** Background updates keep their output in `update.log` in the daemon's log directory. A failed updater clears the progress screen and tells connected clients where to find the error.
- **WSL startup keeps your settings.** The Windows logon task restores the installed port and environment. Startup and restart write the logs used by `dispatch logs`.
- **Uninstall stops the WSL daemon.** Removing the logon task also stops its verified process while keeping your data.
- **AWS CLI on WSL.** Bundled tools now install AWS CLI v2 on Linux using AWS's official user-local installer.
- **Setup instructions match the host.** WSL users get Linux Tailscale instructions. Failed harness installations show their errors in the wizard.

## Validation

These fixes were exercised on Windows Server 2025 with Ubuntu 24.04 on WSL2, including live terminals, files, uploads, Git, settings, and harness installation. Provider account sign-ins and authenticated model conversations still require separate validation; this is not a claim of complete Windows 11 feature parity.

## Updating

Daemon and web app: run `dispatch update`, or use the in-app update prompt.

An older WSL daemon may already be stuck shutting down with a browser connected. Close its Dispatch browser tabs so those connections can finish, then run `dispatch start`. The new shutdown behavior applies after this version is running.
