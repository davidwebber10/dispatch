# Dispatch v2.17.2 — the sort menu sorts files too, newest first

## The change

The project card's sort menu now drives the **FILES** section as well as THREADS.
Pick **Newest**, **Oldest**, **Name (A–Z)**, or **Recently active** and the file list
follows. And the default order is fixed: files now show **newest first** instead of
oldest first.

- **Custom** and **Needs you first** don't map to files (files have no drag order and
  never need you), so in those modes files simply sort newest first — which is what
  makes newest-first the default, since Custom is the default mode.
- The sort runs before the "Files shown" cap, so a capped list shows the newest N
  files, not the oldest N.
- WEB and NOTES keep their existing order.
- Desktop and mobile share the same code path, so both get the behavior.

## What was wrong

The sort menu only fed the thread list. FILES always rendered in raw server order —
`sort_order ASC, created_at ASC` — which put the oldest file first, the least useful
order for a long file list.

## Under the hood

- New pure `sortFiles(items, mode)` in `lib/listSort.ts`, reusing the thread
  comparators. One call site in `ProjectCard.renderSection`.
- New tests: `ProjectCard.filesSort.test.tsx` (5) plus 4 `sortFiles` unit tests.
  Web suite 961/961.

## Updating

**Web-only** — after `dispatch update`, a browser refresh is enough; nothing in core
changed.
