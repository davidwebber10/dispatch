# Dispatch v2.10.0 — configurable sidebar limits for threads and files

## The change

Two new settings in **Settings → General → SIDEBAR**: **Threads shown** and **Files
shown** (independent, default **10** each). A project whose lists run long now shows the
first N rows and a quiet **"Show N more"** row; a click expands the full list. No more
file-heavy projects pushing every other project below the fold.

- Steppers walk 3–50; one step past 50 shows **All** (no cap). Stored per device
  (`dispatch:sidebarMaxThreads` / `dispatch:sidebarMaxFiles`).
- The cap covers the THREADS list and the FILES section only — WEB and NOTES stay full.
- Desktop and mobile share the same behavior (same `ProjectCard`, same settings section).
- The active (highlighted) thread or file is never hidden: if it falls past the cut, the
  cap lifts for that section while it stays active.

## Under the hood

- Drag-reorder on a truncated thread list sends the **full** id order (visible ids first,
  hidden tail appended). `SessionService.reorderTabs` rewrites `sortOrder = index` for
  exactly the ids it receives, so a visible-slice-only payload would have scrambled the
  hidden rows' order.
- New pure helpers `stepSidebarLimit` / `formatSidebarLimit` in `stores/settings.ts` own
  the 3–50↔All stepping, shared by both settings shells.
- New tests: `ProjectCard.limits.test.tsx` (12), plus additions to `settings.test.ts` (5)
  and `GeneralSection.test.tsx` (4). Web suite 896/896.

## Updating

**Web-only** — after `dispatch update`, a browser refresh is enough; nothing in core
changed.
