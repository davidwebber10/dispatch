# Dispatch v2.34.2 — Control Plane tool rows finish instead of running forever

## The change

Agency tool rows in the Control Plane stream (`mcp__dispatch__spawn_agent`,
`mcp__dispatch__complete_agent`, …) no longer sit on the **running…** shimmer forever
after they complete. Spawn/queue/message/start calls render as proper agent cards
again, and `complete_agent` shows as a normally paired tool row.

## Root cause

Two defects in the stream adapter (`overseer/live.ts`), surfaced by the v2.34.0
parity work (before it, the affected items were silently dropped, so nothing visible
broke):

1. Agency tools were matched by bare name (`spawn_agent`), but the live coordinator's
   transcript namespaces them under the MCP server name — `mcp__dispatch__spawn_agent`
   (the agency server registers as `dispatch`). The match never fired, so the calls
   fell into the generic machinery strip and agent cards never rendered live.
2. The orphan-agency-result heuristic dropped every tool result whose JSON carries an
   `agentId` when the call wasn't recognized — including results whose call sat right
   there in the same strip. A call with no result renders the running shimmer forever.

## Under the hood

- `agencyToolName()` matches bare **or** `__`-suffixed agency tool names (the same
  boundary trick `isReportStatusTool` already used — which is why the status card
  never broke).
- The orphan drop now fires only when the result's call is truly outside the window:
  neither registered as an agency call nor routed into a machinery strip.
- Tests: 4 new adapter tests (3 written failing first), full web suite green.
- No data migration: the adapter re-maps the full timeline on load, so existing
  stuck rows render correctly immediately.

## Updating

**Web-only** — after `dispatch update`, a browser refresh is enough; nothing in core
changed.
