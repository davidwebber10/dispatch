# Dispatch v2.13.0 — install a CLI where you hit it, and rain while you wait

## The change

**Installing a missing CLI happens where you notice it's missing.** Select a harness whose
CLI is not on the machine and the New Thread modal replaces Mode, Model, Advanced and Start
with the one thing that matters: the reason, the exact command in case you would rather run
it yourself, and an **Install** button. The card stays selectable and carries an `INSTALL`
sub-label, so you can see what is available at a glance.

This applies to Claude Code and Codex as much as to Grok.

**The update screen has terminal rain.** While the daemon rebuilds itself, falling monospace
glyph columns run behind the card. It is the thing you are actually waiting on, drawn: a
terminal doing work.

## What was wrong

The first pass listed an install row under the harness grid for every missing CLI at once —
clutter that grew with the number of providers, and separated the action from the moment you
hit the problem. Selecting an unavailable harness also did nothing at all, which read as a
broken card rather than a missing dependency.

## Under the hood

The rain is one canvas, mounted **only** while an update is in flight, so nothing animates at
idle. Under `prefers-reduced-motion: reduce` it paints a single settled frame and stops. It
also survives `getContext('2d')` returning null — decoration is never allowed to take down
the screen you are waiting on.

The modal backdrop becomes three layers during an update: the rain, then the same
`rgba(0,0,0,.55)` scrim the backdrop already was, then the card. Keeping the scrim *above*
the rain means the card's contrast is unchanged from before.

Generic glyphs in the New Thread modal now come from Phosphor — the icon set the rest of the
app already uses — for the terminal, caret, check, install and sign-in marks. The three brand
marks stay bespoke, since Phosphor has none.

## Updating

**Web-only** — a browser refresh is enough. Nothing in core changed.
