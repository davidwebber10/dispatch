# Dispatch v2.9.0 — coordinator session controls (Restart / New session / Previous sessions)

## The change

The Control Plane coordinator gets a session menu (the ⋯ kebab) on two surfaces: the
desktop composer row (opens upward) and the mobile header. Three actions:

- **Restart session** — kill and respawn the coordinator in place. The respawn resumes
  the same conversation (`-r`) and re-reads the MCP config, so this is the one-click
  "reload tools" fix for a coordinator holding a stale tool set.
- **New session…** — two-step inline confirm, then the current coordinator is archived
  and a fresh one is find-or-created immediately.
- **Previous sessions…** — the project's archived coordinators, newest first; picking
  one swaps it back in. The current one is archived first, so a project always holds
  exactly one active coordinator. Long lists scroll inside the popover
  (`min(40vh, 320px)` cap) — every row stays reachable.

## What was wrong

`POST /terminals/:id/relaunch` was a silent no-op for a live structured thread:
`restartTerminal` killed only via the PTY manager, so the structured process stayed
alive and `spawnStructured` bailed on `isAlive`. The relaunch now kills the backing
transport (`killCurrentTransport`) before the respawn.

Failed swaps also surface now: the store actions report failure (`Promise<boolean>`)
and the menu stays open instead of closing as if the swap worked.

## Under the hood

- Removed the dead `overseer/WorkerLightbox.tsx` (unimported since 2026-07-20). The
  plan's third surface (a Board coordinator lightbox) pointed at it; coordinators never
  appear on the Board, so no such surface exists.
- New tests: `restart-structured.test.ts` (core), `store-session-actions.test.ts`,
  `CoordinatorMenu.test.tsx`, `Composer.test.tsx` (web).

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`) — the relaunch fix is in core.
The menu itself is web, but shipping it without the core fix leaves Restart a no-op on
live coordinators.
