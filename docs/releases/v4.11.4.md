# Dispatch v4.11.4: Claude sign-in recovers cleanly

## The change

- **A refused sign-in code now says so.** If Claude rejects the code you paste, Dispatch shows the error and a fresh sign-in link right away, instead of waiting 45 seconds and resetting.
- **A thread that hit an expired login recovers after you sign in.** Your next message restarts that thread on the new login, so it no longer stays signed out.
- **Signing in from a thread's card updates that account** instead of adding a new one, and signing in from Settings clears the signed-out cards on other threads ("Signed in. Retry").

## What was wrong

Claude's CLI marks its errors with a leading symbol, and Dispatch missed the "code not accepted" message behind it. A thread that hit "this login reached its time limit" kept its old process, so it kept the old login even after you signed in again.

## Limits

- Only a Claude sign-in from Settings clears cards on other threads. Codex logins and a terminal `claude auth login` do not.
- Restarting a thread on the new login ends any background jobs that thread was running.

## Updating

Needs a daemon update: run `dispatch update`, then reload the app.
