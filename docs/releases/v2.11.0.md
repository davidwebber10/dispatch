# Dispatch v2.11.0 — release notes in the update prompt

## The change

The update prompt now tells you what the update contains. Under "Dispatch vX is ready to
install" there is a **Release notes** row. Expand it and the card widens into a scrollable
panel with the actual notes — headings, lists, code and all.

- **Skipped versions are included.** An install on 2.11.0 that wakes up to 2.14.0 sees the
  notes for 2.12.0, 2.13.0 and 2.14.0, newest first, not just the target's. Up to 10.
- **Settings → UPDATES has the same panel**, so it is reachable after you dismiss the
  prompt. When nothing is pending it flips to **What's new in v2.11.0** — the notes for the
  version you are already running.
- Each entry shows its version, its publish date and its headline, then the note itself.

## Under the hood

Release notes are now **required** to cut a release. `dispatch release` refuses without a
non-empty `docs/releases/vX.Y.Z.md`, and publishes that file as the GitHub Release body
(`--notes-file`) in place of the auto-generated commit list. It also refuses when
`package.json` was never bumped to the version being released — the mistake that used to
leave every install nagging forever.

The update check reads the release *list* rather than `/releases/latest`, filters out drafts
and prereleases, and keeps the notes for every version newer than the running one in
`app_state`. `GET /api/state/update` serves them as `notes`, re-filtered against the running
version on every read, plus `currentNotes` read off disk for the version already installed.

`docs/RELEASING.md` documents the whole path, the note template, and both new guards.

New tests: `notes.test.ts` and an expanded `checker.test.ts` (core), `release.test.ts` (cli),
`ReleaseNotes.test.tsx`, `UpdatesSection.test.tsx` and `releaseNotes.test.ts` (web).

## One thing to expect

An install still on 2.10.0 will show the plain prompt for this release, with no notes row —
the code that reads the notes is *in* this release. The panel appears from the next update
onward.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`). The panel is web, but it has nothing
to show until the core half is serving the notes.
