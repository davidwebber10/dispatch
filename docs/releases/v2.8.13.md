# Dispatch v2.8.13 — A thread's question shows up in thread mode

## The problem

In thread mode you'd sometimes see a thread that had clearly stopped for you, but
nothing in the conversation said what it wanted. The question was real — it just
wasn't where you were looking.

Every thread is told to end its turn with `report_status`, and the old wording
framed the tool as the channel that delivers a question to you: *"put the question
in `ask` … otherwise the human will never see it."* Read literally, that says the
`ask` field **is** how you see the question. So a well-behaved model would route
its real question into `report_status` and leave its actual reply thin or empty.

That works in **board mode** — the Needs Help card reads `lastOutcome`, so the
question shows. But **thread mode reads the transcript**, and the question was
never written there. Same thread, two surfaces, one of them blind.

## The fix — two layers

**1. Reframe the tool (behaviour).** `report_status` is now described as a *status
signal, not a message*: always say the question, result, or feedback in your
normal reply — that reply is what the human reads in the thread — and treat
`summary`/`ask` as a short copy for the board and alerts, never a substitute for
saying it. This stops the question from going missing in the first place.

**2. Surface it anyway (safety net).** Because models are stochastic, thread mode
now shows a declared `needs_you` question as an amber **"⏸ This thread is asking
you"** strip right in the thread — above the composer in Pretty, a top strip in
the terminal — with an **Answer** shortcut. It appears in every place a thread
opens (workspace, the board's over-the-top view, and mobile) because it lives
inside the two transports.

The strip is honest about what it knows: it only surfaces a *declared* ask (the
kind that never reaches the transcript). An **inferred** ask — one the heuristic
read *from* the closing text — is already visible in the conversation, so it's not
duplicated. And live status wins over the persisted row, so the strip clears the
instant you answer rather than lingering.

Verified in a real browser (the strip renders over the board with the right
question and Answer button) plus 16 unit/component tests; the reframed prompt has
its own regression test pinning the new wording and forbidding the old.
