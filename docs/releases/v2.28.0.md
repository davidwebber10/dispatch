# v2.28.0 — hosted boxes, and an update button that works on one

The hosted-box work (a Dispatch daemon per user, running on ECS behind POLYWOOD
OS) had been sitting on a branch since 25 July while main moved 238 commits. It
is merged. Most of it is invisible on a local install — the hosted paths are
gated on environment variables a local daemon does not have — but six things do
change locally, listed at the end.

## A hosted box can update itself

Pressing **Update** on a hosted box used to say:

```
git status failed: fatal: not a git repository
```

The image is built with `COPY . .` and `.dockerignore` excludes `.git`, so the
preflight could never pass. Making git work there would have been the wrong
fix: `/app` lives in the container layer, so a pull and rebuild would succeed
and then silently revert on the next restart. An update that undoes itself is
worse than one that refuses.

So on a box, update means something different in kind: **roll onto a newer
image**. The daemon asks its control plane to re-register the task definition
and replace the container. The existing apply UI is unchanged — same
`update:in-progress` event, same poll-until-the-version-changes reload.

`scripts/build-box-image.sh` is new, and its absence was the underlying bug: the
first image was built by hand and never rebuilt, so the fleet ran 2.8.10 against
a local install on 2.27.0. It tags every build with the package version, which
is what the update check compares against.

## Hosted plumbing (no effect without the environment)

- **Box token gate** (`DISPATCH_BOX_TOKEN`) — a constant-time shared-secret
  check on HTTP *and* on the WebSocket upgrade, which is the one that is easy to
  miss.
- **Base-path serving** (`DISPATCH_BASE_PATH`) — one origin serves a whole
  fleet at `/u/<slug>/dispatch/*`. `<base href>` is rewritten at serve time, so
  one image serves every prefix.
- **OS-brokered MCP tools** — resolved per spawn, so revoking a permission takes
  effect on the next spawn with nothing long-lived left on the box.
- **Terminal-free Claude login** — drives `claude setup-token` over the API, for
  a machine with no terminal in front of it.
- **State projection** — a small heartbeat so the control plane can answer "how
  many threads need input?" without reaching into the box.

## What changes on a LOCAL install

1. **Creating a project creates the directory.** Previously the row was written
   and the first thread's PTY died with `ENOENT` if the path did not exist.
2. **Interactive threads record token usage.** Only scheduled agent runs did
   before; the data now shows up in Analytics.
3. **`/api/claude-auth` exists.** Harmless locally — you sign in at a terminal.
4. **The web bundle builds with `base: './'`** and an injected `<base href>`.
   Identical when served at the root; it is a build-output change.
5. **The WAL pragma is checked.** `createDatabase` used to set
   `journal_mode = WAL` and ignore the result. WAL cannot engage on a network
   filesystem and does not error — it just returns the mode you actually got.
   It now verifies, and falls back to `locking_mode = EXCLUSIVE` only if needed.
   On APFS nothing changes.
6. **Two spawn-env providers were added.** Both return nothing without the
   hosted environment. Main's `withShimPath()` fix is kept as-is.

The update path itself is untouched locally, with a test asserting that the git
preflight and `bin/dispatch update` spawn still run when the daemon is not
hosted.
