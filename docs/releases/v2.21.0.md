# Dispatch v2.21.0 — Grok gets Pretty, and it's the only way Grok runs now

## The change

**Grok threads now run in Pretty mode** — the same structured chat the Claude and
Codex threads have: streamed text and thinking, tool cards with live output,
token usage and the context bar, `report_status` outcomes on the thread card,
and resume across daemon restarts.

**Pretty replaces the Grok TUI.** The PTY never rendered well (mobile paging,
alt-screen churn), so the New Thread modal offers only Pretty for Grok, and any
client that doesn't name a transport gets Pretty automatically. Existing Grok
PTY threads keep working as they are.

Everything a Grok thread could do before still works: the Doppler secrets MCP,
the dispatch peer tools (`report_status`, messaging), model pinning, interrupt,
and coordinator-spawned Grok agents.

## Under the hood

- A third structured manager speaks ACP over `grok agent stdio` — one child per
  thread — and translates the session updates into the same Claude-shaped event
  stream the ChatView already consumes. Resume is `session/load`, whose history
  replay backfills the chat without re-counting usage.
- MCP servers ride `--plugin-dir` on the `agent` subcommand — the trusted plugin
  scope. The same plugin injected via `GROK_HOME` loads untrusted, which leaves
  its tools visible but uncallable (found live; the PTY flow keeps `GROK_HOME`).
- Kill-switch: `DISPATCH_GROK_PRETTY=0` returns Grok to PTY-only.
- Not yet: images in Grok prompts (the channel refuses them), compaction, and
  scroll-up history beyond the live ring.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`) — the transport lives in
the daemon. A browser refresh alone is not enough.
