# Dispatch v2.47.0 — ledger titles and the source panel

Every ledger item now has a short title that chips, card rows and recap lines show instead of a
cut-off question, and a click on a decision's Source line shows the plan section it comes from,
without leaving the Control Plane. (PR #70; small card fixes from PR #69.)

## The change

- **Short titles.** The overseer gives each decision and action a title of a few words, such as
  "Merge board PR #26". Chips show "N80 · Merge board PR #26" (the full question on hover),
  recap lines use the title, and the card shows the title as the headline with the full
  question below it. The daemon requires a title on each new decision and action, and refuses
  a title that is one word, too long, or only a code such as "N41" or "Q12".
- **Existing items get titles on their own.** At its next recap, an overseer with untitled open
  items is asked for their titles first ("Titles first"), then posts the recap. You do not send
  anything. A recap is never blocked.
- **The source panel.** On the card, a plan or doc Source line opens a panel over the chat with
  only that section of the file, and the decision's row marked and scrolled into view. It finds
  the section even when the heading changed a little ("after v3" finds "after v3.2 (…)", "9.
  Owner decisions" finds "9. Decisions recorded"), and it finds a file that only a worktree has.
  When nothing matches, it lists the file's headings. "Open the full file" opens the file tab.
  On the phone, the panel is a full-screen sheet.
- **PR links.** A PR or issue source opens on GitHub in a new tab, for projects whose remote is
  on GitHub.
- **Card fixes.** The Source line shows the file name instead of the full worktree path (the
  path shows on hover), and the header time reads "last change", because the card is live.
- **Plan codes get a name.** When an overseer names a plan question or a build task by its code,
  it adds its short name, for example "A11 (import confirmation)".
- **Less clutter.** The daemon deletes a thread's `thread-<id>.mcp.json` file when the thread is
  archived or its project is deleted; a restored thread writes it again.

## What was wrong

Most questions were longer than a chip, so about three quarters of the chips were cut off.
Decisions pointed at plan files of hundreds of kilobytes with section names that had since
changed, so checking the context meant opening and searching the whole file.

## Updating

Daemon and web app. Run `dispatch update`. Each overseer gets the title rules when it restarts,
which the update does; its next recap asks for the missing titles once.
