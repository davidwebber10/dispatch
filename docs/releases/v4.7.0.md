# Dispatch v4.7.0 — safer file and request handling, and a hosted mode

## The change

On your own computer:

- **Request paths have one spelling.** Dispatch matches routes case-sensitively and without a trailing
  slash. It refuses (`400 bad_path`) a path with a doubled slash, a `.` or `..` segment, a backslash, a `;`
  parameter, a control character, an escape that hides one of those, or a double encoding. The web page,
  the `dispatch` CLI and the SDK never send such a path. If you call the API from a script, write the paths
  as the documentation writes them.
- **One file policy for every route that takes a path** (list, read, download, write, upload, rename,
  delete, the folder browser, a plugin's file, a file reference). It checks the real path, with every
  link followed.
- **The system's own trees are never served:** `/proc`, `/sys`, `/dev` and `/run`, also through a link.
  A removable drive under `/run/media/<user>/` still works.
- **Shell and REPL history files** (`~/.bash_history`, `~/.zsh_history`, `~/.python_history` and more)
  join the credential files that Dispatch never serves.
- **Smart approvals for a chat thread.** A chat thread has a new Approvals setting: Auto (as before),
  Ask or Smart. In Smart mode the harness's own risk check lets routine work run and blocks the rest. A
  blocked action shows a card. "Allow this" allows that one call, one time; the daemon holds the
  decision, so the words of a message cannot approve anything.
- **Transcripts:** the daemon reads a thread's transcript only from a plain file inside a transcript
  folder, opens it without following a link, and checks the open file.
- **The upload library is multer 2** (from the deprecated 1.4.5-lts line). Size limits are unchanged.
  Downloads also send a sandbox policy, and no answer sends `X-Powered-By`.
- **A Pretty thread opens faster.** It shows the newest 60 items first, then fills to 200 above them.
  Older pages still load on demand.
- **Two more themes** in the theme list: POLYWOOD OS Light and POLYWOOD OS Dark.
- **Current Codex models in the picker:** GPT-6 Astra, GPT-6.1 Sol, GPT-6.1 Terra and GPT-6 Luna (the
  models Codex itself offers). `/model 6.1 sol` still works. When your account cannot use a model, the
  thread says so in plain words ("This account cannot use GPT-6.1 Terra. Pick another model.") and does
  not run on another model without telling you.
- **The Inbox tells the agent that a drop arrived.** After `preview`, the agent reads "Sent to the
  person's Inbox: <title>. They can open it now; do not send it again." (the JSON follows).
- **Harness context is not your message.** A system reminder, Codex's environment and AGENTS.md blocks
  and a cut-off turn marker no longer show as a message from you in the thread history: they show as one
  muted "Harness context" line, and never become a thread's title. Anything that is SENT to a thread (by
  you, another thread or an automation) shows as written in the journal, the web page and the thread
  history, whatever its text looks like. No history line is ever hidden: a command echo shows all of its
  words as a muted line.
- **Subagents** (capability `subagents-v1`): a thread lists its subagents (Claude Code agents and Codex
  sub-threads) with their state, shows each one's history, routes a subagent's approvals to you, and can
  stop one. When background subagents finish, their results go back to the main agent in one turn, which
  shows as a notice, never as your message. Only your own message starts a new run of automatic turns. A
  subagent's approval must name its request. See `docs/headless-api.md`, section 12.
- **Plainer Codex errors:** a refused request reads "Codex refused this request: …", and a model the
  account cannot use reads "This account cannot use GPT-6.1 Terra. Pick another model."

Only on a hosted box (no change on your own computer):

- Privilege separation: the daemon is a supervisor, and every agent program and shell runs as a separate
  user without access to the daemon's data.
- Document tools in the image, so an agent can open what a person attaches, and curl to download a file
  (where the box may connect is the platform's egress control): unzip, zip and 7z; PDF text,
  pages and repair (poppler, qpdf); OCR (tesseract, English); pandoc; jq, sqlite3, file; fonts; and
  Python (no pip) with pandas, openpyxl, python-docx, python-pptx, pypdf, pdfplumber, Pillow, matplotlib,
  duckdb and more. `/etc/dispatch/tools.json` lists them with versions, and a thread's environment note
  points to it. No LibreOffice.
- A Codex thread no longer shows its history twice to a client that reads it over REST: the history Codex
  replays when a thread resumes is not sent to that client live. A Codex thread with no readable transcript
  still shows that replayed history (it is then its only history).
- You can sign out of the box's own Codex (ChatGPT) login from the Connections page (capability
  `codex-signout-v1`). While a Codex thread works, the sign-out waits and says so; otherwise every Codex
  thread ends (it starts again, signed out, on its next message) and that login's usage figures go.
  Signing out of Claude now answers once Claude's own sign-out ran.
- Codex can run shell commands on a hosted box. Codex's own sandbox (bubblewrap) cannot start there, so a
  Codex thread runs without it and the box is the sandbox: the command runs as the agent user, with no new
  privileges, without access to the daemon's state, and with network reach set by the platform. Approval
  `never` stays forbidden. Trade-off: with no inner sandbox, Codex asks for approval only when the model
  decides to. A Codex coordinator keeps its read-only sandbox and cannot run shell commands on a hosted box.
- A Codex thread started with no model picked runs GPT-6.1 Sol on a hosted box (the daemon's default and the
  image's Codex config). A pick still wins; `DISPATCH_CODEX_DEFAULT_MODEL` sets another default.
- Codex threads run in fast mode (the `priority` service tier) when the signed-in account offers it for the
  model (Codex's model list says so; the box log line `codex.tiers` shows what the account offers), and a
  Sol thread with no effort picked runs at low. The task environment can turn it off for the whole fleet
  (`DISPATCH_CODEX_SERVICE_TIER=off`) without a new image; a resumed thread then also runs at standard
  speed, and a resume that Codex refuses at that tier starts again with no tier. The box log names the
  tier Codex reports; `thread.fast.refused` says when Codex did not apply the tier, and why. The image no longer ships the daemon's sources and tests.
- The heartbeat also reports the last 24 hours of use, the usage-limit levels and the disk use, for the
  platform's fleet page. The box log names the model each thread asked for and the model its harness
  runs, and logs each Inbox drop and list (no content). Read-only requests never count as activity for
  idle sleep.
- A business profile with a route table (default deny), the company tools as one MCP server per system,
  an MCP allow-list, no status tool and an answer-first reply rule for chat threads, a hardened image,
  and the headless API for a view in another app (`docs/headless-api.md`, `docs/hosted.md`).

## Updating

Needs a daemon rebuild and restart: run `dispatch update`. If you call the HTTP API from your own
scripts, check that they use the documented paths (see "Request paths" in `docs/security.md`).
