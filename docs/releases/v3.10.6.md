# Dispatch v3.10.6: security leftovers (SEC-05 middle, SEC-21, SEC-23)

## Calls without a key can no longer do the risky things (SEC-05, PR #126)

- A request with no owner token, thread key or signed-in browser now gets 401 when it tries
  to send a message, answer a held call, start or relaunch a thread, replace a thread's
  config, start a terminal, or change, delete or import an integration.
- Reads, hooks, the browser app, the CLI and adding, renaming, stopping or restarting a
  thread still work as before. Scheduled tasks and restart or restore still run without a
  key; `docs/network-access.md` lists these exceptions.
- This catches mistakes and stray scripts. It is not a wall against a program already
  running as you on the Mac.

## Threads can list integrations, with values hidden (PR #125)

- A thread key can now list integrations. Tokens, headers, URL secrets and secret-looking
  command arguments are masked. The owner still sees stored values.
- The "owner only" refusal now names the route, so a thread knows what it was refused.

## Notification devices and stability caps (SEC-21, SEC-23, PR #124)

- **Settings lists the devices that get notifications**, with a short label and the last
  send time, and each one has Revoke. A revoked device turns its switch off.
- **Turning notifications on and off** now goes through one queue. The newest choice wins,
  and a stuck step gives up after 10 seconds.
- **Caps**: push devices (`DISPATCH_MAX_PUSH_SUBSCRIPTIONS`), file watches
  (`DISPATCH_MAX_WATCHES`), stream line size (`DISPATCH_MAX_STREAM_LINE_BYTES`) and the
  per-connection send buffer (`DISPATCH_WS_MAX_BUFFERED_BYTES`, `DISPATCH_WS_BUFFER_GRACE_MS`).
  A phone that is slow but still reading is not dropped. Chat history replay is paced.
- **Crash logging**: unexpected errors are logged with a per-minute limit
  (`DISPATCH_MAX_CRASH_LOGS_PER_MINUTE`, 0 = log all) instead of filling the log.

## Known limits

- If a notification on/off step times out, the switch can show the wrong state until you
  reopen Settings. A follow-up will fix this.
- Real push delivery to a phone was not tested before release. No spawn-tree cap yet.

## Under the hood

- PRs #124, #125, #126. Each had Codex review until it said ship; #124 also had an Opus
  review. CI passed on each. 95 core tests in the MCP files fail on main before and after.

## Updating

Run `dispatch update` (or `./bin/dispatch update` from the repository folder), then reload the
app on each phone. This release adds two columns to the push devices table (migration
`015-push-label`); it runs on its own at start.
