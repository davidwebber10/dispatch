# Dispatch v2.47.7 — a lost Claude conversation no longer fails silently, and a safer daemon.pid

Two fixes for structured (Pretty and Control Plane) Claude threads and the WSL daemon. (PRs #79 and #78.)

## A lost Claude conversation (#76)

When Claude no longer has a thread's conversation (its transcript was cleaned up), resuming it
fails. Before, Dispatch showed only "Turn ended with an error" and tried the same resume again
each time you opened the thread, sent a message, or the Control Plane acted.

Now:

- Dispatch sees Claude's "No conversation found" error, forgets the old conversation, and the
  next message starts a new one. The old conversation id is kept in the thread's settings.
- The chat and the Control Plane show the real reason for an error: Claude's own message, why a
  thread could not start, and why a message could not be sent.
- Claude's error output is written to the daemon log (`dispatch logs`).
- Dispatch still reads Claude's last message when it arrives just after the process exits.

## daemon.pid (#56)

The daemon now writes `~/.dispatch/daemon.pid` only after it has its port, and removes the file
on shutdown only if the file still holds its own process id. A second launch that fails because
a daemon is already running no longer overwrites the running daemon's id, so `dispatch restart`
on WSL finds the right process.

## Updating

Server and web app. Run `dispatch update`, then reload the page.
