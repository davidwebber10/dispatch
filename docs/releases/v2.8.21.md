# Dispatch v2.8.21 — an autocorrect toggle, and a soft-key row that scrolls

Follows [v2.8.20](./v2.8.20.md), which turned spell check on in the mobile CLI composer.

## The change

Three related things, all in the composers.

### 1. The Pretty composer spell-checks too

It carried the same `autoCorrect="off" spellCheck={false}` pair that the CLI composer
did. It now spell-checks and autocorrects, **unconditionally** — no toggle. The Pretty
composer takes prose only; no shell input ever reaches it, so there is nothing to
protect from a correction.

### 2. The CLI composer's spelling help is now a toggle

The CLI/PTY composer is different: a run of shell commands is exactly when autocorrect
gets in the way. So it gets an **"Aa" key** in the row above the input.

- Accent-coloured when on, struck through and muted when off.
- On by default.
- Persisted per device (`dispatch:ptyAutocorrect` in localStorage), so it survives a
  reload rather than resetting each time you open a thread.

### 3. The soft-key row scrolls left/right

The row above the composer divided its width evenly between its keys:

```jsx
flex: '1 1 0', minWidth: 0
```

That is a layout which **cannot overflow** — every extra key just makes them all
narrower, so `overflow-x: auto` on the parent would never have triggered. Fixing it
meant changing the children as much as the parent.

Keys now keep their natural width (`flex: '0 0 auto'`, `minWidth: 46`) and the row
scrolls. This was already a problem before the toggle existed: `keysFor()` returns 6
keys for Claude, 4 for Codex and 7 for shell, plus `/` — a shell thread was dividing
the row nine ways and each key was well under a hittable size.

## What deliberately did not change

`autoCapitalize` stays **off** in both composers, in every state of the toggle. It is
the one attribute that would actively damage input — it would send `Git status` and
`Rg -n` into the PTY. Spelling help without forced capitalisation is the combination
that fits a composer aimed at an agent.

`autoComplete` also stays off in both. It governs browser form-autofill, which is
unrelated to spelling and has no business offering saved values here.

The slash-command search field keeps all four off — it matches command names, where
spelling help is only noise.

## Activating this

**Web-only** — a browser refresh is enough. No daemon rebuild, no restart.

Four tests cover it (CLI default on, the "Aa" key turning it off and persisting, the
row's scroll layout, and Pretty being unconditional), each verified by mutation:
reverting the change fails the matching test and only that test.
