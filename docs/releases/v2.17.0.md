# Dispatch v2.17.0 — one list of harnesses, and guards that keep it honest

## The change

Adding a harness is now one entry per package instead of six scattered edits.

Nothing about using Dispatch changes. This removes the cause of three bugs that already
shipped, so the fourth does not happen.

## What was wrong

Adding Grok meant editing the same list in six unrelated places, and missing one failed
**silently** every time:

- Grok threads spawned, ran, and were filtered out of the sidebar — invisible, unreachable.
- Grok got no peer tools, because one eligibility check still read `claude-code || codex`.
  Without `report_status` a Grok thread could not declare how its turn ended.
- Grok's MCP servers were registered but its system prompt was dropped, so the agent had the
  tools and no idea what they were for.

One cause, three separate releases to fix. The Setup wizard had drifted too: `npm i -g`
against core's `npm install -g`, and a login command of bare `claude` — the TUI that never
prints its sign-in link.

## Under the hood

**Core** gains `providers/agent-types.ts` — `AGENT_TYPES`, `THREAD_TYPES`, `AGENT_CLI` and
the type guards. It has no imports at all, so db, routes, providers and sessions can each use
it without risking an import cycle. `types.ts`, `db/terminals.ts`, `routes/terminals.ts`,
`setup/detect.ts` and `isPeerEligible` all derive from it.

**Web** gains `lib/harnesses.ts`, where `HARNESSES` is the ordered source for the New Thread
picker and everything else — type lists, models, install and login commands — derives from
it. `NewThreadModal`, `ProjectCard` and `SetupWizard` stop keeping their own copies.

The guards matter as much as the constants:

- A core test asserts `AGENT_TYPES` and the provider registry cannot drift, naming the
  offending provider. I verified it by adding a fake provider and watching it fail, rather
  than trusting a green test.
- Web asserts its lists really are derived from `HARNESSES`, and that every harness has its
  own sidebar colour instead of falling through to the plain shell's grey.

`docs/providers.md` shows all four injections — MCP servers, status hooks, system prompt,
session id — across the three harnesses side by side.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`).
