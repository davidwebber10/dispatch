# Dispatch v2.36.1 — Coordinators can no longer drift into native subagents

Fixes coordinator drift into the native `Agent` tool (observed in PW Legacy and
Explorer): work spawned that way is invisible to `list_missions`/`list_agents`
and bypasses the typed-agent flow. (PR #43.)

## The gap

v2.35.0's `coordinatorToolPolicy` already denies `Agent`/`Task` — but the CLI
auto-approves native orchestration tools without emitting a `can_use_tool`
request, so the membrane never saw the spawn. (The drifted subagents' own tool
calls DO route through the membrane, which is why write enforcement still held.)

## The fix

Coordinator spawns now pass `--disallowedTools Agent Task Workflow`, removing
the tools from the model's toolset entirely — a tool that does not exist cannot
be drifted into, at turn 1 or turn 900. Verified against the CLI: removal is
from the session toolset itself, matching is exact-name (`TaskCreate` etc.
untouched), and unknown names are ignored (covers the `Task`→`Agent` rename
across CLI versions). The membrane policy deny stays as a backstop and now
covers `Workflow` too.

Typed agents, role runners, and non-claude providers are unchanged.

## Updating

`dispatch update` (restarts the daemon), then **respawn each coordinator
session** — live sessions keep their old toolset until respawned.
