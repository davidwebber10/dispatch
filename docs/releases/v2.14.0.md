# Dispatch v2.14.0 — no more false auth banners, and a Sign in button

## The change

**The authentication banner only appears when a program actually tries to open a browser.**

**A harness that is installed but signed out now offers to sign you in.** Select it and the
New Thread modal shows a Sign in panel instead of options for a thread that would just stop
at a login screen. It opens a `Sign in — <CLI>` thread running that CLI's plain login
command, which prints the sign-in link — so the banner can hand it to your phone.

**Dismiss clears the whole queue** and shows a count when more than one is waiting.

## What was wrong

Reading every thread's output for sign-in links was far too loose a signal. Any thread that
merely *printed* an auth-shaped link raised a banner — including an agent writing about
OAuth. In practice an agent's own prose produced a stream of them, each needing its own tap
to dismiss because the banner showed one at a time.

The captured links were often unusable too. The character set allowed non-ASCII, so a link
rendered inside a box-drawn panel swallowed the box characters, and one followed by an arrow
in prose swallowed the arrow — both percent-encoded into a broken link.

Output is now read in exactly one place: a thread Dispatch itself started to sign in. Every
other thread relies on the `$BROWSER` / `open` shim, where an actual exec proves intent.

## Under the hood

The login commands matter more than they look. Bare `claude` and bare `grok` open a
full-screen TUI that renders the sign-in link as an unclickable region and never prints it —
which is exactly the dead end you hit on a phone, with no way past it. The plain commands
print the link. Verified for all three under a real PTY:

| CLI | Command | Prints the link | Execs `$BROWSER` |
| --- | --- | --- | --- |
| Claude Code | `claude auth login` | yes | yes |
| Codex | `codex login` | yes | no |
| Grok | `grok login` | yes | no |

`LOGIN_COMMANDS.claude` was `claude` — the trap — and is now `claude auth login`. A sign-in
thread spawns that command **directly** rather than typing into a shell, so nothing races a
shell prompt and the watched process is exactly the login.

Also fixed: the new banner introduced an infinite render loop. A zustand selector returning
`.filter(...)` hands back a new array every render, so the snapshot never settles and React
throws "Maximum update depth exceeded". Caught by the existing suite before shipping.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`). The scanner gate and the sign-in
spawn are both in core.
