# Dispatch v2.21.3 — Grok can see pasted images, and the Pretty composer lines up

## The change

**A screenshot pasted into a Grok Pretty thread actually reaches Grok.** The
composer already staged the image, but the daemon rewrote it as a text marker
("this Grok channel cannot receive images") before it hit the wire. Grok now
gets a real image block, so it can see the picture.

**The Pretty composer's "Message…" line sits level with the attach and send
keys.** The placeholder used to hang a few pixels below the icons.

## What was wrong

Grok’s agent declares `promptCapabilities.image: false`. Dispatch trusted that
and downgraded every image to a sentence. A live probe showed the channel
accepts `{type:'image', data, mimeType}` and the model does see the picture —
the declaration is stale. Only a URL-source image (which ACP has no wire shape
for) still falls back to a marker.

The composer row pins attach/send at 34px and `align-items: flex-end`. The
textarea had no padding, so its one-line box was shorter than the keys and
the placeholder sat low.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`) for the Grok image
fix; the composer alignment rides the web bundle it ships.
