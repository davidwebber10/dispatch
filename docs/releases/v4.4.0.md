# Dispatch v4.4.0 — An effort picker and a "/" menu for Pretty threads, overseers and Chat

## At a glance

- **Pick the effort next to the model.** The model chip's card now has an effort picker.
- **A "/" menu above the composer.** Type `/` for `/model`, `/effort`, `/compact`, `/stop`, `/cli` and `/restart`. On the phone, the **+** menu has a **Commands** row.
- **Overseers and Chat get the same controls.** The Control Plane has the chip and the menu. Chat has one model and effort for all of Chat.
- **`/restart` always asks first,** whether the thread is idle or working.

## Effort

- Claude offers low to max. Codex offers the levels that the thread's model takes, so the list differs by model.
- The pick applies to that thread only. It is not a default for new threads.
- Grok and OpenCode keep model switching. They have no effort control.
- A saved pick survives a restart, `/restart`, a switch to the CLI and an update.

## The "/" menu

- Chat offers `/model`, `/effort` and `/stop`. Overseers have every command except `/cli` and `/restart`.
- Dispatch runs a known command. It is not sent to the model. Put a space before it to send it as text.
- A `/word` that Dispatch does not know goes to the harness. Codex shows a hint first.
- A bad value keeps your typed text, so you can correct it.

## When a change does not take

- Model and effort cannot change while a turn is running. Wait for the turn to finish, or stop it.
- If a harness refuses a change, you see a line in the thread and in the card. Chat shows the line above its box.
- A dropped connection or a slow page load no longer loses a saved pick.

## Known limits

- A refused Codex model that has no earlier saved value cannot be restored automatically.
- A CLI that answers after the 15-second limit may still apply the change.

## Updating

This release changes the daemon. Run `dispatch update` (or `./bin/dispatch update` from the
repository folder). The daemon restarts once. Then reload the app.
