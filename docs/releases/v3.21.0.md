# Dispatch v3.21.0: more than one account per harness

## The change

- **Settings → Accounts.** The signed-in accounts under Claude and under Codex. The CLI's
  own login on the daemon's computer is always there. Add a Claude account with the same
  login box as before (open the page, paste the code): the daemon keeps that account's token.
  Add a Codex account: it gets its own folder, and a "Sign in — Codex" thread opens to run
  `codex login` for it. Pick which account new threads use by default. Remove an account.
- **New Thread → Account.** When a harness has more than one account, the modal shows an
  Account row. The thread runs on that account for its whole life, across resume, relaunch
  and daemon restart. A thread with no account of its own uses the default.
- **Usage per account.** One ring and one card per account, named "Claude · Work" and so on,
  each with its own plan, windows and spend. Codex credits and banked resets are per account.
- Your single saved Claude login from before becomes the account "Dispatch login" and stays
  the default.

## Limits in this release

- A Codex Pretty thread runs on the CLI login only: the shared Codex app-server cannot take a
  per-thread login. The New Thread modal disables Pretty for an added Codex account.
- A usage-limit pause is shown per tool, not per account.
- Chat (the coordinator) and automations use the default account.

## Under the hood

- `auth/accounts.ts`: `~/.dispatch/accounts.json` (0600) with tokens and defaults;
  `spawnEnv()` is the per-thread overlay (`CLAUDE_CODE_OAUTH_TOKEN`, or empty for the CLI
  login; `CODEX_HOME` for an added Codex account) on both the PTY and the structured path.
- Snapshots keyed by tool and account; the gauge, the readers and the routes loop accounts.
- Routes: `GET /api/accounts`, `POST /api/accounts/claude/login`, `POST /api/accounts/codex`,
  `PUT /api/accounts/:provider/default`, `DELETE /api/accounts/:provider/:id`.
- Spec: `docs/superpowers/specs/2026-11-06-multi-account-design.md`.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
