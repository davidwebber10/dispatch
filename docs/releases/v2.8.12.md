# Dispatch v2.8.12 — Project timestamps track thread activity + smoother spinner

## Project "last active" now updates live

Work in a thread and the **project's** timestamp updates with it — so sorting projects by
**Most recent** floats the one you just touched to the top, immediately, instead of leaving
it stale until a full reload.

**What was wrong:** the backend was already stamping a project's `last_activity_at` on real
thread activity (the database was always correct). But the live `session:status` event the
client receives carried only the status, not the timestamp — so the project card kept
rendering the old "last active" until the whole project list was re-fetched. The rail's
*thread* row refreshed on open; the *project* never did.

**The fix:** `session:status` now carries the session's freshly-bumped `lastActivityAt`, and
the projects store adopts it. Because the daemon only bumps the stamp on **real** work, a
passive status flip (attaching to a thread, a resize repaint) omits the field, so the store
never reorders the list for a non-event. Sort-by-recent now reflects reality live.

## Smoother thread spinner

The little loading spinner on threads could shimmer/wobble. An odd-sized spinner (11px)
centered in an even-height row lands its rotation center on a half-pixel, so a plain
`rotate()` re-samples the circle against the pixel grid every frame; in the busy,
live-updating thread list it also competed with React re-renders for the main thread and
dropped animation frames.

It now renders on its own compositor layer (`will-change: transform`): the circle is
rasterized once and the texture is spun on the compositor thread — smooth regardless of
sub-pixel origin or how hard the main thread is working.

## Under the hood

- `session:status` is enriched with `lastActivityAt` at all four broadcast sites
  (StatusService aggregate, the pty-timing rollup, and both server exit/rollup paths), via a
  new light `sessionsDb.getLastActivity` single-column read.
- `useProjects` patches `lastActivityAt` from the event only when present (no clobber on
  passive flips). Desktop + mobile "recent" sorts already key on `lastActivityAt`, so they
  reorder reactively.
- `Spinner` gains `will-change: transform`.

The `session:status` change is a daemon change (rebuild + restart / auto-update); the spinner
and store changes are web-only (a refresh picks them up).
