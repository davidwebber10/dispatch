# Dispatch v2.39.0 — Codex coordinator, and Codex workers fixed

Codex can now run the Control Plane, and Codex workers work properly. (PR #47.)

## The change

- **Codex as the coordinator.** The setup card now offers Codex as well as Claude Code for
  the coordinator. A Codex coordinator is held to the same ground rules as a Claude one:
  - It runs in a read-only sandbox. Every escalated shell command is declined.
  - It can write only its own memory, in `~/.codex/dispatch-coordinator`.
  - It can use only Dispatch's own MCP tools. Other MCP servers run outside its sandbox.
  - Its approvals always come to Dispatch, never to Codex's own reviewer.
- **Codex workers now work as intended.** Each Codex worker gets its agent-type
  instructions and its own Dispatch identity, and can call MCP tools.

## What was wrong

- **Codex workers (2.38).** A Codex worker got no agent-type instructions. All Codex threads
  shared the identity of whichever one started first. On current `codex-cli`, every MCP tool
  call (`report_status`, secrets, integrations) was rejected. A Codex worker cut off by a
  restart was never resumed. All four are fixed. A Codex thread started on 2.38 keeps the
  setup it started with; a new thread gets the instructions.
- **A thread could run a command in a shell tab.** `message_thread` / `message_agent` typed
  the text into a shell tab, and the shell ran it — outside the sender's ground rules. Dispatch
  now refuses to message a shell tab.
- **A restart dropped interrupted work.** `dispatch restart` / `dispatch update` marked a
  mid-turn coordinator or agent as finished, so it never resumed. It now resumes at boot.
- **One Codex thread, one tab.** Opening a Codex thread that is already open in another tab
  is now refused. Before, the older tab silently stopped receiving updates.
- **The setup card now shows a failed Start** instead of doing nothing.

## Under the hood

The shared `codex app-server` now starts with no thread-specific settings. Each thread
carries its own MCP servers and persona on `thread/start` / `thread/resume`. Every review
round of this change, and its fixes, is recorded in
`docs/superpowers/reviews/2026-09-23-pr47-phase2-review.md`.

## Updating

Daemon + web. Run `dispatch update` (its restart applies the daemon side), then reload the
PWA / browser tab. A Codex coordinator needs the Codex CLI installed and signed in.
