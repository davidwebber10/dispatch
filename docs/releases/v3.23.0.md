# Dispatch v3.23.0: see and switch a thread's account

## The change

- **Which account a thread runs on.** On the phone, the line under the thread name now ends
  with the account: "Proj · Pretty · Work". The Details pane (the desktop right-hand panel,
  and "Thread details" on the phone) has an Account row. An unpinned thread shows the
  harness default with "(default)".
- **Switch account…** A new row in the thread menu (right-click, the ⋯ button, long-press),
  and a "Switch Account" button in the Details pane. It lists the signed-in accounts of the
  thread's harness with the current one marked. Pick another and confirm: the thread is
  pinned to it and restarts under that login.
  - Claude Code resumes its session. The CLI stores sessions by folder, not by login.
  - Codex starts a fresh Codex session: its sessions live in the login's own folder. The
    Dispatch history stays. The dialog says so.
  - A working thread can switch; the dialog says the turn stops.
  - A Codex Pretty thread cannot pick an added account: the shared app-server has one login.
    Switch it to CLI mode first.

## Under the hood

- `PATCH /api/terminals/:id/account { accountId, force? }` (owner only): a server-side merge
  of `config.accountId`, then a kill and respawn of a running thread. A stopped or queued
  thread just takes the pin. `SessionService.switchAccount`, with
  `setAccountDirectory` for validation and the default.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
