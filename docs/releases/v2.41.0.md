# Dispatch v2.41.0 — Control Plane analytics

The Analytics screen now shows how the Control Plane works, next to token usage. (PR #55.)

## The change

- **A view switch.** A `Usage | Control Plane` switch sits beside the Analytics title. The
  Project, Range, and Provider filters are shared, and a switch never resets them. The screen
  opens the view you used last; a first visit opens Usage. On a phone, the bottom tab now reads
  "Analytics".
- **Control Plane numbers.** Six tiles: sessions (Control Plane threads, archived ones
  included), active days, missions started, missions completed, agents started, and the Control
  Plane's share of recorded tokens.
- **Charts.** Agents started per day by type (implementer, researcher, planner, review), tokens
  per day for the Control Plane and for its agents, messages per day (yours to the Control Plane,
  and the Control Plane's to agents), and missions completed per week.
- **Tables.** By project, by agent type (agents, average turn, tokens, and CLI mix, for example
  "codex 19 · claude-code 11"), and the missions active in the range with an Active or Completed
  status.

A mission counts as completed when no agent of it is working or queued and it has had no
activity for 7 days. So the latest week is always low; the weekly chart marks it "still
settling".

## Known limits

- The messages chart counts Claude Code threads only. Codex and Grok threads do not record
  message sources yet.
- Token numbers count recorded usage only, the same data as the Usage view.
- When you archive a project, its numbers leave the Control Plane view.

## Updating

Daemon and web app. Run `dispatch update`, then reload the Dispatch tab or the PWA.
