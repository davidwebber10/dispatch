# Dispatch v4.5.0 — Faster over Tailscale, more reliable, safer

## At a glance

- **Faster, especially over Tailscale.** A warm start shows your threads in about 100 ms. A thread you switch back to shows at once. Your message, an archive and a rename show at once. Replays and history pages are compressed (a 230 KB page is now 2–4 KB), and a reconnect sends only what the app is missing.
- **More reliable.** A thread's status lives in one place, so "Working" no longer sticks. Notices and wake-ups are saved and delivered exactly once, also across a restart. A hung thread gets a quiet "No output for N min" mark. A thread's questions survive a restart.
- **Safer.** Credential files (Dispatch's token and database, `~/.ssh`, CLI logins, `~/.git-credentials`, keychains) are never served by a file route, by any path or link. Integration values are masked for local programs. Plugins can no longer read another plugin's data.
- **New:** a command palette that opens threads, a "Needs you" list (Alt+N), desktop links for each thread, a diff review with Approve and Discard, a worktree option for a new thread, "Why is this thread in this state?" and `./bin/dispatch doctor`, a Previews tab per thread, an "Active within" filter, and Claude limit resets on the usage card.
- **Restart once** after you update: the daemon changed.

## Usage window

- Claude limit resets (the Fable launch resets) show on the Claude card, with **Use** that opens claude.ai.
- A compact flyout: each account is its own card with its email; the open thread's account has a "This thread" tab and comes first, in the flyout and in the rail.
- **Refresh** reads every account now, then shows the new "Updated" time. A rate-limit wait from Anthropic is always respected.
- An account whose sign-in cannot read usage says so ("This sign-in can run threads. It cannot read usage figures.") instead of failing quietly. Dispatch waits longer after a 429 and after a refused sign-in.

## Threads and navigation

- The command palette (Cmd+K) opens threads and projects, starts a new thread, and has "Next thread that needs you".
- A "Needs you" section lists threads that wait for you, then errors, then threads that are silent too long.
- Each thread has its own address on desktop and phone; Back and Forward work.
- The thread list has a status filter and **Active within** (last hour, today, this week, this month). A working thread always stays.
- **Diff review** (Files → Review): each changed file with its diff. Approve stages a file (no commit). Discard asks on the page, names each file, and keeps a copy in git. Nothing else is ever removed.
- **Run in a new worktree** when you start a thread (off by default): a new branch and folder; your project stays as it is.

## Previews

- A thread shows its own previews (a tab on desktop, a row in the phone's thread menu); a project shows the project's; the Previews screen shows all, with filters.
- Lists show 20 at a time with **Show older**, and small copies of images. The iPhone page no longer crashes on many large screenshots.

## Under the hood

- The daemon has one builder for the app and its tests, a split session service, a shared core for the Pretty transports, typed thread settings, and a message journal with a sequence per thread.
- History reads only the part it needs: paging a 100 MB transcript no longer stalls the daemon.
- The web app loads less code first (396 KB → about 280 KB on a phone) and redraws less.

## Settings you can change (all off or unchanged unless you act)

- **Doppler token scope** (Settings → Secrets): your existing connection keeps "every thread". "Only threads I choose" gives the token only to threads you switch on in the thread menu. The Doppler tools in threads work in both modes.
- **`DISPATCH_BIND=127.0.0.1`** keeps the daemon off the LAN. `dispatch status` shows the listen address.
- **Cloudflare Access check:** `./bin/dispatch access cloudflare --team-domain <team>.cloudflareaccess.com --aud <AUD>` makes the daemon verify the Access token on an allowed host. `--off` turns it off.

## Changes to know

- Three routes now need proof that the request is yours: pairing codes, secret values, and the integration export. The web app works as before, also on a plain-http tailnet address.
- Plugin SDK version 2: a plugin gets an object bound to its own id. `sdk.api` and `sdk.stores` are deprecated; they still work and log one warning. A version 1 plugin can no longer pass another plugin's id.
- The client's old "busy from frames" fallback and the daemon's synthetic settle frame stay for this release only and are removed after v4.5.0.
- The first start runs database migrations (journal, delivery record, saved questions, indexes). Old scheduled threads are not woken.

## Updating

Run `dispatch update` (or `./bin/dispatch update` from the repository folder). The daemon restarts once. Then reload the app. On a phone, open Dispatch through the `tailscale serve` https address and add it to the home screen again, so the offline cache works.
