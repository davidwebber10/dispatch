# Dispatch v3.4.6: an old sign-in banner closes when a newer one replaces it

## The change

- **The banner always shows the sign-in that is still waiting.** When a CLI restarts during
  a sign-in, it starts a new login with a new link. The old banner now closes on its own
  instead of staying on top. Restarts happen after an MCP reconnect, or when Claude Code
  stops a server that hasn't started within its 5-minute limit.

## What was wrong

Signing in from a phone takes a while. During that time an MCP server could restart, and its
old callback listener on the Mac went away with it. The banner still showed the old link, so
you signed in, pasted the callback, and it went nowhere.

## Under the hood

- A new request closes any open request from the same thread for the same authorize address
  (same origin and path). Requests from other threads or other services are left alone.
- New test in `auth/service.test.ts`.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update`, then reload the app.
