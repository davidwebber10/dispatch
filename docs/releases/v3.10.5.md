# Dispatch v3.10.5: a worker reports to the thread that started it

## Reports go to the right thread

- **No more cross talk in the overseer.** Before this release, every worker in a project
  sent its reports to the project's overseer, even when you or another thread started it.
  So one thread's code reviewers could flood the overseer and make it open items it had no
  business tracking.
- **Now a worker reports to the thread that started it.** Workers the overseer started
  still report to the overseer. Workers your own thread started report to that thread.
  Threads Chat started report to Chat.
- **A stopped starter is not woken.** If the thread that started a worker is stopped,
  archived or deleted, the report is dropped and logged. It does not fall back to the
  overseer.
- **Only the overseer's own workers count for it.** Owner decisions, the batch line and the
  interim recap count only workers the overseer started.
- **Questions stay visible to you.** A question from a worker that a plain thread started
  goes to that thread, and the worker still shows as needing you.
- Workers started before this release with no recorded starter still report to the
  overseer. `docs/report-routing.md` explains the rules. There is no setting for this.

## Under the hood

- PR #122. Codex reviewed it in two rounds. The new routing tests pass. It was not tried

## Updating

Run `dispatch update` (or `./bin/dispatch update` from the repository folder), then reload the
app on each phone. No database change in this release.
