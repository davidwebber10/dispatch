# Dispatch v2.36.2 — Thread content fits narrow phone screens again

Fixes the mobile regression where thread (chat) content overflowed the right
edge of a narrow screen (iPhone SE class) and paragraphs wrapped far wider than
the viewport. (PR #44.)

## The cause

The paint-settle-gate back-port (2026-09-01) wrapped the thread message
scroller in a new flex-row div without `minWidth: 0`. A flex item refuses to
shrink below its content's min-content width, so one long unbreakable token —
a joined identifier in inline code — silently set the width of the whole
column, and every paragraph wrapped at the token's width instead of the
screen's. The Control Plane stream was never affected (its scroller sits in a
flex column). Root-caused by extracting both layout chains and measuring them
in headless Chrome: 613px of content in a 500px window before the fix, an
exact 500px after.

## The fix

- `minWidth: 0` on the thread scroller's wrapper and root — the regression.
- Markdown inline code gets `overflow-wrap: anywhere`: a long token now wraps
  mid-token instead of clipping at the screen edge, and its min-content
  collapse structurally prevents this bug class from recurring. Fenced code
  blocks keep their horizontal scroll.

## Updating

Web-only. `dispatch update`, then reload the PWA / browser tab. No session
respawn needed.
