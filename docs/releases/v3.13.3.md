# Dispatch v3.13.3 — usage limits: correct chip, more harnesses

## The change

Fixes to the usage-limit chip and banner that shipped in v3.11.0. Codex terminals, Grok and
OpenCode are now covered as well.

## Usage limit chip and banner (#129)

- A limit with no reset time keeps the chip red until the limit clears. It clears on a fresh
  reading under 100% for the window that hit the limit, or when the thread resumes.
- When the last automatic retry fails on a stopped thread, the chip goes back to normal. The
  banner keeps the thread listed.
- A blank or stale usage report can no longer clear a red chip.
- 99.96% counts as under the limit. Only 100% stays red.
- A plain "weekly limit" stays red while any weekly window is at 100%.
- A slow settings load no longer overwrites a change made on another device.
- Two database migrations (016, 017) record when a limit was detected and when it cleared.

## More harnesses (#130)

- Codex in a terminal now pauses on its usage-limit message (tested with a simulated message).
- Grok chat pauses on a 429 and retries every 30 minutes, up to 5 times.
- Limit text quoted in a reply or inside a code block no longer pauses the thread.
- A thread woken after a limit is marked working, and a repeat limit pauses it again.

## Not covered

- A Codex stop that does not say which limit was hit clears on any reading under 100%.
- OpenCode and Grok in a terminal have no limit detection yet.
- Not tested on a phone or against a real limit.

## Updating

Run `dispatch update`, then close and reopen the app on your phone.
