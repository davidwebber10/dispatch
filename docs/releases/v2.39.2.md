# Dispatch v2.39.2 — a GPT worker runs on Codex, not on Claude

The Control Plane now passes the harness with a non-Claude model. (PR #53.)

## What was wrong

- **The coordinator did not know about `harness`.** Its instructions listed `spawn_agent` and
  `queue_agent` without the `harness` parameter. Only the live tool schema had it. A coordinator
  that lost the schema in a long session (for example, after a context compaction) sent the model
  alone.
- **The model does not choose the harness.** A worker with `model: "gpt-6-astra"` and no harness
  ran on the default CLI, usually Claude Code. The Claude CLI then failed with "There's an issue
  with the selected model".

## The change

- The coordinator's instructions (Claude and Codex) now list `harness` in both tool signatures.
  They say that the model never picks the harness, with the example
  `{ harness: "codex", model: "gpt-6-astra" }`.
- The `harness` description on `spawn_agent` and `queue_agent` says the same.
- Dispatch refuses a GPT, `o3`-style, or Grok model on Claude Code before it creates the thread.
  The error tells the coordinator which harness to pass, so no broken agent stays behind.

## Updating

Daemon only. Run `dispatch update`. Each coordinator gets the new instructions the next time it
starts.
