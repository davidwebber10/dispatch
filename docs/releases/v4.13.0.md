# Dispatch v4.13.0: every part of Dispatch uses the Claude account you chose

## The change

- **Chat, thread titles, the usage check and the sign-in checks now use an account.** Chat and a new thread use the default account. A title uses the account of its thread. Before, they could use an old saved sign-in that no page showed.
- **A sign-in inside Dispatch always lands in a named account.** You see it in Settings → Accounts. The card asks before that account becomes the default. Your default never changes without a question.
- **The sign-in card names both ways** when the Claude login of your computer is signed out. Sign in with `claude` in a terminal and keep your claude.ai connectors. Or sign in inside Dispatch and get a login that has no connectors.
- **The Accounts page says which logins have claude.ai connectors.** Open an account to see the line.
- **Dispatch no longer puts a Claude token in the environment of its child processes.** A thread gets the login of its own account and no other. A plugin worker, a hook and a shell tab get none.

## What was wrong

Dispatch had two sources of a Claude login. A thread took the login of its account. Chat, titles, the usage check and the sign-in checks took an old saved sign-in when one existed, whatever the default account was. So Chat could run on a different login than your threads, and its usage was counted on that login.

On one test install with the login of the computer as the default and an old saved sign-in present, Chat, titles and the usage check all ran on the old sign-in. In this release they run on the default account.

## Check your install

- **Most installs: nothing to do.** The update changes no account and no default.
- **Chat can move to another login.** If your default account is the login of your computer, and you once signed in from a card inside Dispatch, Chat used that card sign-in until now. From this release Chat uses the login of your computer: its usage counts there, and Chat has your claude.ai connectors.
- **If Chat answers "Not logged in" after the update,** your default account is the login of your computer and that login is signed out. Open Settings → Accounts and make "Dispatch login" the default, or run `claude` in a terminal and sign in there.
- **A shell tab no longer sees a Claude token from Dispatch.** A `claude` command that you start in a shell tab uses the login of your computer.

## Limits

- Removing an account does not stop the threads that run on it.
- A scheduled job has no account setting of its own. It runs on the default account.
- Codex accounts did not change.

## Hosted boxes

A box that signs in with Claude Code's own login behaves as before. A thread on a company model did not change.

## Updating

Needs a daemon update: run `dispatch update`, then reload the app.
