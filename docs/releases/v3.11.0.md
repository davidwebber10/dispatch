# Dispatch v3.11.0: usage gauge, limit warning and paused banner

A 5-hour Claude limit used to stop every agent at once with no warning. The numbers only
showed in one thread's Details panel. This release puts them where you can see them (PR #128,
issue #127).

## Usage chip

- The desktop rail shows `5h 46` and `wk 21` above the connection dot.
- The phone header shows the higher figure next to the alert bell.
- Click or tap opens the full table.
- The chip turns amber at the warning level. It turns red while that provider has a paused
  thread. It dims when the figures are more than 30 minutes old.

## Paused banner

- A red strip says which agents are paused, why, and when they resume. For example:
  `Claude agents paused: session limit, resumes 3:11 PM (2 threads)`.
- Click it to open the first paused thread. The × hides it on this device until the next pause.

## Warning push

- The daemon sends one push when a window crosses the warning level. It sends one per window,
  and it remembers that across a restart.
- Codex figures refresh every 60 seconds from the last active Codex thread.

## Settings

A new Usage limits section, on desktop and phone.

- **Warn at**: 50 to 99, default 80. Applies to the whole daemon.
- **Push alert at the warning level**: default on. Applies to the whole daemon.
- **Show the paused banner**: default on. Applies to this device only.

The Details panel now says "No figure reported" instead of "Under the warning level". Claude
Code 2.1.316 reports usage on every turn, so the old wording was wrong.

## Known limits

- Real push delivery to a phone was not tested. Neither was a real limit stop.
- CLI threads report nothing. The chip shows the last figure from a Pretty thread or Chat.
- Not in this release: a guard that stops the coordinator spawning at the limit, and Codex
  live updates.

## Under the hood

- Web: 2095 tests pass. CLI: 95 pass. Core: 95 of 96 failures pass once the Dispatch
  environment variables are cleared. The last one, `devices-integration`, fails the same way
  on main.

## Updating

Run `dispatch update` (or `./bin/dispatch update` from the repository folder), then reload the
app on each phone. There is no database migration.
