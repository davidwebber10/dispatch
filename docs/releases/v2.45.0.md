# Dispatch v2.45.0 — the overseer gets its own memory

Each Claude overseer now loads only its own memory at each start. It can still read your own
threads whenever you ask or a task needs them, and anything it takes from them keeps its
origin. (PR #65.)

## The change

- **Its own memory folder.** A Claude overseer keeps its notes in
  `~/.claude/dispatch-overseer/<project>/memory`, and only that folder loads at each start.
  On its first start after the update, Dispatch copies the overseer's own earlier notes there.
  Nothing is deleted.
- **Your threads, on demand.** Your own Claude threads keep the project's shared memory, as
  before. The overseer reads those notes, or a thread's history, when you ask or when a task
  overlaps one of your threads.
- **The origin stays visible.** A ledger card can now name one of your threads as its source:
  `Source: your thread "…"`. Such an item enters the ledger only when you say so, and the
  overseer cannot decide it itself.
- **Shared notes on purpose.** When your threads must know something, the overseer writes one
  note into the shared folder, starting with "From the overseer:".
- **A narrower write scope.** A Claude overseer may write only its own folder and the project's
  shared folder. Before, it could write anywhere under `~/.claude`.
- **Project rules as one line.** The recap shows "Project rules: 13 in force (type "show
  rules")" instead of the full list.

## What was wrong

Claude Code keeps one memory folder per git repository, and every Claude session in it loads
that folder: the overseer, its agents and your own threads. In one project, 19 of 29 notes came
from the user's own threads, and the overseer imported their open items into its decision
ledger as its own work.

## Updating

Daemon. Run `dispatch update`. Each Claude overseer restarts with its own memory folder and its
copied notes, in the same conversation; you do not need a new session. The Codex overseer
already had its own folder and only gains the new rules.
