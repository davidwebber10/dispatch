# Dispatch v3.11.1: usage limit banner and chip fixes

Fixes for the v3.11.0 usage chip, warning push and paused banner, found in two independent
reviews (PR #128). No database migration.

## What was wrong, and what changed

- **Archived threads stayed "paused".** Archiving a thread that was paused or stopped on a limit
  left the red banner and the red chip on, a stopped one for good. Archiving now clears the
  pause, and a restart clears any left over.
- **The chip stays red only while the limit is on.** After the window resets, the chip goes back
  to normal (or amber at the warning level), even if a thread that gave up is still stopped. The
  banner still lists that thread until you message it.
- **A slow reload could hide the banner.** On a reconnect, an older answer could overwrite a
  newer pause. The daemon now stamps each summary and the app keeps the newest.
- **Codex figures went stale during a long turn.** The 60-second refresh skipped a Codex thread
  that was still working but had no recent activity stamp. It now polls working threads too.
- **A second warning push for one window.** A reset time that shifted by a few seconds across a
  10-minute boundary counted as a new window. Two reset times within 10 minutes are now one window.
- **Phone: the Chat paused banner did not open Chat.** From inside a project or a thread, one
  step back left you on the project screen. It now goes back to the start screen, where Chat is.
- **The x on the banner.** It now holds until a newer pause starts. Before, one thread resuming
  could bring the banner back, and a second thread pausing could not.
- **Settings > Usage limits.** The push switch now follows a change made on another device.
- The 3.11.0 note now says that the Codex refresh runs only while a Codex thread is active or working.

## Known limits

- Real push delivery to a phone and a real limit stop were not tested.

## Updating

Run `dispatch update`, then reload the app on each phone.
