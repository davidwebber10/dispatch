# Dispatch v4.8.0 — company models for Claude Code on a hosted box

## The change

On a hosted box:

- **A Claude Code thread can run on a company model.** The platform can grant a person a company model
  (the first one is `claude-opus-5-5`). The platform holds the model credential. The thread's model
  traffic goes through the daemon to the platform's proxy. The person's own Claude login keeps working
  for every other thread.
- **No Claude login is needed for it.** A person with a company Claude model and no Claude login of
  their own can create and run a Claude thread.
- **Which login a thread uses.** A new thread on a granted company model uses the company model when the
  person has no usable Claude login, or when the request asks for it (`config.modelSource: "company"`).
  When the platform puts the person's own seat first and they are signed in, the thread uses their own
  login. `config.modelSource: "subscription"` asks for the own login. The thread keeps its source when it
  resumes, and `GET /api/chats` shows it as `modelSource`.
- **A model that is not granted is refused** with "This model is not available to you.", for a new thread
  and for a model switch.
- **The thread holds only its own key.** The box token and the model credential never reach a thread. The
  daemon's relay accepts only a thread's own key, from the same machine, for a granted model.
- **One model for the whole thread.** Claude Code's subagents and small calls use the same granted model.
  Web search and fast mode are off on a company model.
- **New capability `company-claude-v1`.** The platform shows the company Claude option only to a box that
  reports it. A box reports it only while Claude Code's login is not forced (below).

On your own computer nothing changes: without the platform's `modelAccess` answer, every thread works as
before.

## The hosted image

- **The forced Claude login is now a drop-in.** `forceLoginMethod: "claudeai"` left the image's main
  Claude Code policy file. It is the root-owned file `10-dispatch-login.json` in Claude Code's managed
  folder (`/etc/claude-code/managed-settings.d`). Claude Code 2.1.322 reads it there (measured). Every box
  has it from the first start.
- **The daemon lifts it only for a company-billed person:** while the platform grants a company Claude
  model and turns the person's own Claude login off. It writes it back as soon as that stops. Without
  an answer from the platform, the login stays forced.
- **`company-claude-v1` is reported only while the login is not forced**, so the platform offers the
  company model only where Claude Code can use it.
- **A start that is not root must find the drop-in.** If `/run/dispatch` is an empty volume and the box
  does not start as root, the box refuses to start.
- A company thread also gets `CLAUDE_CODE_ATTRIBUTION_HEADER=0`.

## Updating

Run `dispatch update`. Nothing to configure on a local install.
