# Dispatch v3.8.1: report turns lose Monitor, schedule floor holds

A follow-up to v3.8.0, from gaps found while validating it. It adds no approval prompt, no
permission mode and no new limit.

## The change

- **Report-started Chat turns can't run shell commands through `Monitor`.** The report-turn
  deny list now includes `Monitor`, `TaskOutput` and `TaskStop`. The older names `BashOutput`
  and `KillShell` stay for older CLIs. Everything report turns kept in v3.8.0 is still there.
- **The shortest schedule gap (`DISPATCH_MIN_SCHEDULE_MINUTES`) can't be bypassed.** It is now
  checked when a schedule is created, when it becomes recurring, when its rule changes, and when
  it is switched on. A stored cron rule denser than the floor is held to it at run time,
  counting from when the last run actually fired. Rules like `0,1 * * * *` are refused at any
  time of day. Normal rules (every 5 minutes, hourly, daily, weekdays, monthly) and one-time
  schedules work as before.

## Known items

- At the default floor of 1 minute, `* * * * *` (every minute) is allowed.
- A schedule that is overdue because Dispatch was down, then edited, may run twice close
  together once.
- The 413 "too large" error page still shows a stack trace and the install path.

## Under the hood

PR #113. Two rounds of Opus and Codex review; CI passed.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
