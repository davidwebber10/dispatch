# Dispatch v3.26.1: a stop signal after report_status, and thoughts that stay open

## The changes

- **report_status tells the model its turn is over.** Some models treat any tool result as a cue
  to keep going. An OpenCode thread on Qwen answered, called report_status, read `{ok:true}`,
  then invented the next question and answered it, turn after turn. The tool result now says
  "Your turn is over. Write nothing more and call no other tool; the human speaks next.", and
  the tool description and the peer prompt say the same. Claude and Codex already stop, so
  nothing changes for them.
- **An open thought or tool result stays open while the turn streams.** In Pretty mode, a thought
  (thinking block) or a stray tool result that you opened snapped shut as soon as the model wrote
  more. Each new block remounts the turn, and the whole-message event changes every block's id at
  once. The open state now lives under a key that survives both, so what you opened stays open.
  Tool calls already kept their state; thoughts and stray results now do too.

## Updating

Daemon and web client. Run `dispatch update` (or `./bin/dispatch update` from the repository
folder), then reload the app. A running thread gets the new report_status result at its next
call; the new prompt text reaches threads that start after the restart.
