# Dispatch v2.43.0 — chat-only models in OpenCode

An OpenCode thread on a model that cannot call tools now runs as a chat thread instead of
failing on its first turn.

## The change

- **Chat-only threads.** When you pick an OpenRouter model that has no tool-capable
  endpoint, such as `cognitivecomputations/dolphin-mistral-24b-venice-edition`, Dispatch
  starts OpenCode with every tool turned off. The model answers. It cannot run commands,
  edit files, or use the Dispatch peer tools.
- **A `CHAT ONLY` tag in the picker.** Settings → Harnesses → OpenCode → "Add a model" marks
  such catalog rows. You can still add them.
- **Local models too.** For a model id outside OpenRouter, such as `ollama/<model>`, Dispatch
  reads the models.dev catalog that OpenCode itself uses. A model it does not know, or a
  catalog that is unreachable, keeps today's behavior and sends tools.

## What was wrong

Every agent harness sends its tool list on every request. OpenRouter rejects such a request
for a model without a tool-capable endpoint with `No endpoints found that support tool use.
Try disabling "<tool>"`. The named tool is only the first one in the list. Dispatch did not
check tool support before the first turn, so the thread errored immediately.

## Under the hood

- `settings/model-capabilities.ts` answers the tool-support question from the cached
  OpenRouter catalog and from models.dev. The create route awaits it for a picked model and
  pins `config.toolsDisabled` on the thread. The spawn path reads a synchronous cache for a
  thread created without a pick, and the daemon warms both catalogs at boot.
- The OpenCode config for such a thread uses `permission: {"*": "deny"}` and no MCP block.
  The deprecated `tools: {"*": false}` is not enough: the permission block wins over it, so
  the usual `bash: "allow"` entry re-enabled bash and the request still failed. Verified
  live over `opencode acp`.
- New tests cover the catalog flag, the capability lookup, the config writer, the create
  route, and the picker tag.

## Updating

Daemon. Run `dispatch update`. The picker tag needs a browser refresh.
