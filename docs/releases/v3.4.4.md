# Dispatch v3.4.4: usage limits in Details and the context popup

A small feature release (#107). Nothing to set up.

## What you will notice

- **Usage limits in thread Details.** Under THREAD DETAILS, a thread shows its account's limits:
  Session (5h), Weekly, and any other limit the CLI reports under its own name (Fable, Opus,
  Sonnet, Usage credit). An "As of" line shows when the numbers were last reported, and a paused
  thread shows its "Paused: ... resumes ..." line from v3.4.3.
- **On the phone too.** The phone has no Details pane, so the same section shows in the Context
  window popup. Tap the context ring under the composer. The Mac popup shows it as well.
- **Claude numbers.** Claude Code only sends a percentage past its 90% warning level. Below that
  the panel says "Under the warning level" instead of guessing a number.
- **Per account.** Numbers from one login are never shown for another. Grok and opencode show
  "Not reported".

## How it works

Numbers come from what the CLIs already send during a turn (Claude `rate_limit_event`, Codex
`rate_limits`). Dispatch does not poll any usage service.

## Known items

- Checked with automated tests and a 375 px layout check on stand-in data, not on a real phone.
- Phone threads in CLI (terminal) mode have no context ring, so they show no usage.
- A brand-new thread has no context ring until its first reply, so no popup yet.
- Chat's own popup does not show limits.
- A Claude process that keeps running across a login switch may report under the old account.

## Updating

Run `dispatch update`, then reload the app.
