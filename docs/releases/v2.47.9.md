# Dispatch v2.47.9 — Claude agents get their prompt from a private file

Dispatch now gives Claude Code its appended system prompt in a private file, not as text in the
command line. (PR #81.)

## What was wrong

Every Claude agent that Dispatch runs had its full prompt in its command line. Any process on
the machine can read a command line, and process monitors log it. A command such as
`pkill -f until` matched every agent whose prompt contains the word "until", and 14 agent
threads stopped at the same time. v2.47.8 blocks these commands in Pretty and Control Plane
Claude threads; this release removes the prompt text that such a pattern can match.

## The change

- When the installed Claude Code is 2.1.69 or newer, Dispatch writes the prompt to one file in
  `~/.dispatch/prompts` and passes `--append-system-prompt-file` with its path. The folder and
  the files are readable only by your user account.
- Claude reads the same text as before. The agents see no change.
- With an older Claude Code, or when `claude --version` fails, Dispatch keeps the old text form.
- Dispatch reads the version of the `claude` that the agents run, at startup and then every hour.
  A thread that starts before the first read uses the text form.
- Threads with the same prompt share one file. Dispatch deletes a file that no thread used for
  7 days.

Each thread uses the file from its next start.

## Updating

Server only. Run `dispatch update`.
