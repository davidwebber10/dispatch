# Dispatch v3.10.2 — Security leftovers: no scripts in SVGs, no paths in errors

## The fixes

- **SVG, HTML and XML files can't run scripts.** Files shown in Previews and Chat are now sent
  in a sandboxed mode with `nosniff`, so a file a thread hands you can't run code in the app.
  Images still show normally.
- **Error messages no longer show paths on your Mac.** The oversized-upload error used to show
  internal server details and file paths; it now returns a short JSON error. The same clean-up
  covers chat attachments, Finder reveal, folder create and browse, Doppler save, role enable
  and the role list.
- **Editing a schedule no longer moves its next run.** Changing only a schedule's name or prompt
  keeps its next run time. Before, an overdue run could be skipped, or a run held back by the
  1-minute minimum could run again a minute later. Changing the timing still sets a new next
  run. The 1-minute minimum and the 60-thread cap are unchanged.

## Under the hood

- PR #116. New shared `clientMessage()` in `packages/core/src/http/client-message.ts` turns
  errors into safe text for every route that used to return `err.message`.
- Every fix has tests that fail before it and pass after it. Codex reviewed three rounds.
- Known leftovers: an oversized-document error still names a path inside the project, and an
  OpenRouter error passes its network message through. Neither shows a path on your Mac.

## Updating

Run `dispatch update` (or `./bin/dispatch update` from the repository folder), then reload the
app on each phone.
