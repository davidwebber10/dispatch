# Dispatch v4.0.0: plugins, the Coach, themes

## The changes

- **Plugins.** A plugin is a folder under `~/.dispatch/plugins/<id>` with a `plugin.json` and a
  `web.js`. It can add screens (a rail item on the desktop, the Plugins tab on the phone, up to two
  tabs of their own), Settings sections, thread and project menu rows, composer buttons, header
  buttons, commands for the new ⌘K palette, and content in named places of existing screens. Save
  a file and the app reloads the plugin. A plugin that throws shows a red card; `?safe` or
  Settings → Plugins → Safe mode loads none. The guide is `docs/plugins.md`.
- **Storage, keys and permissions.** Each enabled plugin gets its own key and its own documents
  and settings on the daemon. What a plugin may read is listed on its Plugins page row.
- **The model part.** A plugin can give every thread instructions and an MCP server, run a script
  on thread events (a prompt, a tool call, a turn's end, a status), and make its own model calls
  (metered on the Plugins page). Prompt text reaches a plugin only with `read:prompts`.
- **Workers.** A plugin can run a process the daemon keeps alive while it is enabled, fed with the
  daemon's events and cron jobs, with logs and Restart on the Plugins page.
- **Marketplaces.** A marketplace is a git repository: add its URL in Settings → Plugins. The daemon
  clones it with your own git login, so a private repository is a private marketplace. Browse,
  install, update (the Settings dot and banner list plugin updates), roll back, pin, and auto-update.
  There is no public marketplace: a team keeps its own repository. `dispatch plugin publish` opens
  a pull request with your plugin.
- **Skills.** A skill is a folder with a `SKILL.md`. Enabled skills reach every thread's prompt;
  Settings → Skills switches them per project.
- **Previews is now a bundled plugin.** It works as before (the eye with the count, the sheet, the
  history, the viewer). Your old previews move into it once, at the first start.
- **Right-column tabs.** A plugin can add a tab to the desktop right column, after Details and
  Files; on a phone it opens from the thread's ⋯ menu.
- **Export, import, and keep data on removal.** A plugin row's ⋯ menu exports the plugin's
  documents and settings as one file, and imports one (merge or replace). Remove keeps the data by
  default, so a reinstall gets it back; the Remove dialog can also download it first.
- **Model calls choose harness, model and budget.** A plugin's model call can run on Claude, Codex
  or OpenRouter (or Automatic: the account with the most room), with the model it names. Each call
  is metered with its model, account and cost on the Plugins page. A budget per plugin (a share of
  the weekly limit, or dollars a week on OpenRouter) is a hard stop, and no call takes the last 10%
  of a 5-hour window.
- **The Coach (bundled, on by default) replaces the Prompt coach.** It looks at how you work
  with AI and suggests one small next step at a natural break, on the weakest of five measures,
  toward goals you can set. It can suggest a skill (and create it in one click after you review
  it) or a plugin for an agent to build. Talk with it about your own use: it answers from what it
  has seen and says so when it has too little. Ask it to review a thread, a project or your last
  week, or to look back at your last 30 days; it shows the cost first. You choose how often, what
  it remembers, and what it may spend (default: 3% of your weekly limit). A welcome card comes
  first and can turn it off; if you had turned the Prompt coach off, the Coach stays off.
- **Skills from a draft.** `POST /api/skills` and `d.actions.createSkill` create a skill after a
  review sheet; nothing is written before Create.
- **Themes.** Settings → Appearance → Theme: System, and light and dark themes with swatch
  previews. The terminals, the file editor and the charts follow the theme; plugins do too when
  they use the app's colors.
- **A file named by its bare name opens.** A chat link such as `LEARNINGS.md` now opens the file
  wherever it is in the project, with a note that says where.
- **Added Claude accounts show their usage at once.** An account added with a `setup-token`
  cannot read the usage endpoint; Dispatch now reads its limits with one tiny turn signed in as
  that account, right after you add it, instead of waiting for you to use it.
- **Codex accounts sign in with a code.** Adding a Codex account shows a link and a one-time code
  (Codex's device sign-in), so it works from a phone; a failed sign-in shows why, and an account
  with no login has Sign in again.
- **Usage rings.** In a thread, the header shows only the account that thread uses; tap it and its
  card says "This account". The ring counts the 5-hour and weekly limits (a model's own weekly
  limit only in a thread on that model), and Settings → Usage limits can show the percent used in
  the ring instead of the logo.
- **Filters and dropdowns are one design.** Threads, Previews and Analytics share one filter bar
  (search, a Filters button, removable pills), and every dropdown in the app is the same custom
  control; plugins get both as `d.ui.FilterBar` and `d.ui.Select`.
- **Thread menu.** The ⋯ menu is grouped: four tiles (Rename, Branch, Account, Alerts), View,
  Plugins, a folded More, and Archive last. The desktop opens the same menu as a fly-out.
- **Phone.** The bottom tabs remember where you were (tap the tab again to go back to its top;
  Projects goes up one level per tap). The Plugins tab is a plain list and a plugin opens under a
  thread-style header. The CLI composer grows over the terminal instead of pushing it, has a
  handle to shrink it, and a keyboard button opens a short panel of keys that pages left and
  right. A long thread name scrolls slowly instead of ending in "…".
- **Settings → Plugins** is a short list with a switch per plugin; tap one for its permissions in
  plain words, status, actions, and a folded Developer section. The Coach's settings are grouped
  the same way, with a project picker instead of a wall of checkboxes.

## Off by default

Any plugin folder that appears on its own (for example one a thread wrote): enable it on the
Plugins page. The Coach is on (unless you had turned the Prompt coach off); its welcome card, or
the Plugins page, turns it off.

## Updating

Daemon and web client. Run `dispatch update` (or `./bin/dispatch update` from the repository
folder), then reload the app.
