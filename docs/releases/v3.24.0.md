# Dispatch v3.24.0: account names and emails, and the phone's project header

## The change

- **Settings → Accounts shows who each account is.** The email and plan now fill in for
  every account, the CLI login included. Codex reads them from its own login file. Claude
  asks the profile call with the account's token; an added account keeps the answer.
- **Rename an account.** A pencil on each row. The CLI login takes a name too; an empty
  name restores "CLI login (this computer)".
- **Removing an account names its threads.** The confirm lists the threads pinned to the
  account and says they will use the default account the next time they start. On remove,
  the daemon drops the pin from those threads, so that is what happens. Each row also shows
  how many threads are pinned to it.
- **Phone: the project screen's header matches the thread screen's.** Usage, then one ⋯
  button. The ⋯ menu holds Previews (with the unseen count), Rename project and Archive
  project. The Previews eye button is gone from that header.

## Under the hood

- `PATCH /api/accounts/:provider/:id { label }`, `GET /api/accounts/:provider/:id/threads`;
  `DELETE` now answers `{ unpinned }`. `GET /api/accounts` carries `threadCount`, and fills
  `email`/`plan` with a 3 s bound on the Claude profile call (cached 10 min).
- `parseCodexAuth` reads `tokens.id_token` (email, `chatgpt_plan_type`) without verifying it.

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
