# Dispatch v3.28.0: plugins

DRAFT — the version bump and the release are the owner's call.

## The changes

- **Plugins.** A plugin is a folder under `~/.dispatch/plugins/<id>` with a `plugin.json` and a
  `web.js`. It can add screens (a rail item on the desktop, the Plugins tab on the phone, up to two
  tabs of their own), Settings sections, thread and project menu rows, composer buttons, header
  buttons, commands for the new ⌘K palette, and content in named places of existing screens. Save
  a file and the app reloads the plugin. A plugin that throws shows a red card; `?safe` or
  Settings → Plugins → Safe mode loads none. The guide is `docs/plugins.md`.
- **Storage, keys and permissions.** Each enabled plugin gets its own key and its own documents
  and settings on the daemon. What a plugin may read is listed on its Plugins page row.
- **The model part.** A plugin can give every thread instructions and an MCP server, run a script
  on thread events (a prompt, a tool call, a turn's end, a status), and make its own model calls
  (metered on the Plugins page). Prompt text reaches a plugin only with `read:prompts`.
- **Workers.** A plugin can run a process the daemon keeps alive while it is enabled, fed with the
  daemon's events and cron jobs, with logs and Restart on the Plugins page.
- **Marketplaces.** A marketplace is a git repository: add its URL in Settings → Plugins. The daemon
  clones it with your own git login, so a private repository is a private marketplace. Browse,
  install, update (the Settings dot and banner list plugin updates), roll back, pin, and auto-update.
  The public one is `https://github.com/polywood/dispatch-plugins.git`. `dispatch plugin publish`
  opens a pull request with your plugin.
- **Skills.** A skill is a folder with a `SKILL.md`. Enabled skills reach every thread's prompt;
  Settings → Skills switches them per project.
- **Previews is now a bundled plugin.** It works as before (the eye with the count, the sheet, the
  history, the viewer). Your old previews move into it once, at the first start.
- **The Prompt coach (bundled, off by default).** After each prompt you send, it shows one
  observation and one better version above the composer, and your habits over the week. Turn it on
  in Settings → Plugins; each judged prompt is one model call.
- **A file named by its bare name opens.** A chat link such as `LEARNINGS.md` now opens the file
  wherever it is in the project, with a note that says where.

## Off by default

The Prompt coach, and any plugin folder that appears on its own (for example one a thread wrote):
enable them on the Plugins page.

## Updating

Daemon and web client. Run `dispatch update` (or `./bin/dispatch update` from the repository
folder), then reload the app.
