# Dispatch v2.30.1 — no more crash dumps during updates

## The change

`dispatch update` (and any daemon shutdown) no longer crashes the daemon with
`TypeError: The database connection is not open`. Shutdowns are clean, and
`dispatch.err.log` stays free of the stack dumps that made routine updates look
like failures.

## What was wrong

Shutdown closed the SQLite handle while node-pty was still flushing final
output from live threads. A straggler output event then reached the agent-run
activity updater, which touched the closed handle and threw. launchd recovered
the process each time, so updates still went through, but the daemon crashed
mid-shutdown (51 dumps had accumulated in one install's log), and a crash there
can skip the settle-to-waiting status writes. The exit handlers already
guarded against this window; the activity path was the one write left
unguarded. Reported as #18.

## Under the hood

One `db.open` guard in `AgentService.updateRunFromTerminalActivity`, plus a
regression test that closes the handle and asserts the call degrades to a
dropped write. Core suite 1599/1599.

## Updating

Needs a **daemon rebuild/restart** (`dispatch update`) — the fix is in core.
Fittingly, the update that installs it is the last one that can still crash
the old daemon on its way out.
