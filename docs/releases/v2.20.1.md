# Dispatch v2.20.1 — the browser banner stops calling every link a sign-in

## The change

When an agent opens a URL in your browser, the relay banner now says what it
actually caught. A real sign-in still shows 🔑 **"Authentication required"**
with the callback-paste field for remote devices. Any other link — an artifact
preview, a docs page — now shows 🔗 **"Link to open"** with just the
"Open in browser" button.

## What was wrong

The `open`/`$BROWSER` shims relay **any** http(s) URL an agent tries to open,
but the banner titled all of them "Authentication required". An agent sharing
an artifact preview looked like an OAuth prompt, complete with a callback-paste
field that had nothing to receive.

## Under the hood

- The banner classifies client-side: a `terminal-output` request is a sign-in
  by construction (the output scanner only reports sign-in URLs); a
  shim-relayed URL is checked against the same signal list core uses
  (`oauth`, `login`, `device`, `verify`, …).
- Three new `AuthBanner` tests cover the plain-link title, the hidden paste
  field, and the terminal-output override.

## Updating

**Web-only** — a browser refresh is enough.
