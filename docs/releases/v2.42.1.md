# Dispatch v2.42.1 — doppler_get_secret shows a value only on request

The Doppler tool that agents use to read a secret no longer returns the value by default.
(PR #61.)

## The change

- **Facts by default.** `doppler_get_secret` now returns whether the secret exists, its
  length, and its type. It does not return the value.
- **The value only on request.** With `reveal: true`, it returns the value. It never returns
  the raw form, which can hold `${OTHER}` references, or the note.
- **A missing secret** now shows as `exists: false`, not as an empty value.
- **Guidance.** The tool description and the agent prompt say to use a secret through
  `doppler run --project <p> --config <c> -- <command>`, and to set `reveal: true` only when
  you ask to see the value.

## What was wrong

A tool result goes into the agent's transcript, into each later request to the model
provider, and into the session files on disk. `doppler_get_secret` returned the whole secret
(raw, computed, and note), so a value that an agent only needed to use ended up in all of
those places.

## Known limits

An agent's shell has `DOPPLER_TOKEN`, so it can still run `doppler secrets get NAME --plain`.
This change is a safe default for normal use, not a hard block.

## Updating

Daemon. Run `dispatch update`. A thread gets the new Doppler tool when it starts, so restart
an open thread to use it. The web app did not change.
