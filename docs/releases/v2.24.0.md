# v2.24.0 — names from the model, order from the bar

Two quality-of-life upgrades: threads get real titles, and compaction stops
lying about message order.

## GLM-titled threads (OpenRouter)

When the OpenRouter key resolves (the same configurable Doppler secret the
OpenCode harness uses), new claude-code/codex threads are titled by a fast
`z-ai/glm-5-turbo` call over the first prompt — a concise 3-5 word name
instead of the prompt's first 48 characters.

- Picked by a 6-model GLM shoot-out: 1.0-1.4s per title, no latency spikes,
  100% compliance with the 3-5 word limit. ~$0.0002 per title.
- `reasoning: {enabled: false}` is load-bearing — GLM models default to
  thinking mode and burn the whole token budget with a null completion.
- Strictly additive: no Doppler, no key, model error, or timeout (8s cap)
  all fall back to the existing prefix-derived name, silently. A user
  rename still wins any race.
- The key is resolved per attempt, so connecting OpenRouter (or rotating
  the key) upgrades naming without a restart.

## Compacting bar (Pretty mode)

The bottom-left "Compacting context…" spinner is now a full-width bar pinned
in the timeline at the point the compaction began, with an elapsed timer and
an indeterminate sweep (Claude Code reports no compaction progress, so a
percent bar would be an invention).

Messages sent during a compaction render BELOW the bar — they queue on the
CLI's stdin until compaction ends, and the position now says so. A caption
("The message below sends when compacting finishes.") appears when at least
one message is queued. When compaction ends the bar disappears and the
timeline re-merges in normal order.

## Updating

Core + web: pull, rebuild, and restart the daemon (`pnpm build`, then
restart). The compacting bar is live on refresh; thread naming activates
with the daemon restart.
