# Dispatch v2.44.1 — imported decisions no longer flood the first recap

After an overseer imports its open items into the decision ledger, its first recap shows the
top 5 decisions as full cards and one line for every other decision. (PR #64.)

## The change

- An imported decision never counts as "new" in the recap. Imported decisions compete for the
  top 5 like older items: first the ones that hold up work, then the oldest. Every other one
  gets one line with its question and the recommendation. Type `show N7` or `show all` for
  more full cards.
- Decisions that arrive after the import keep the normal rule: each new one gets a full card.

## What was wrong

The first rollout import of v2.44.0 put 52 items into one project's ledger. Every imported
decision counted as new, so the first recap showed every open decision as a full card. That
recap was about 24,000 characters long.

## Updating

Daemon. Run `dispatch update`. If you used the import workaround (calling `ledger_list` once
without posting it), you can drop that step now; it does no harm.
