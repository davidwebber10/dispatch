# Dispatch v4.12.0: a plugin can find archived threads

## The change

- **A plugin with the `read:threads` permission can now list a project's archived threads.** Before, it could read an archived thread only when it already knew the thread's id.
- **No new permission.** `read:threads` already gave a plugin the open threads of a project, a thread by id and its transcript, archived or not. The archived list joins them.
- **Nothing changes for threads or for you.** A thread's own key is still refused on that list. The Archived section of the app works as before.

## Why

Dispatch archives an idle thread after a few days when you turn that on. A plugin that reports on past work, such as a weekly review, then lost those threads: on one install, almost half of the threads that worked in the last 7 days were already archived.

## For plugin authors

`GET /api/sessions/<id>/terminals/archived` answers a plugin key that lists `read:threads`. On an older Dispatch the same call answers 403, so a plugin that must run on both treats a 403 as "not available". See `docs/plugins.md`, "Permissions and the plugin key".

## Updating

Needs a daemon update: run `dispatch update`, then reload the app.
