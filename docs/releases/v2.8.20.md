# Dispatch v2.8.20 — the mobile terminal composer spell-checks

## The problem

The message bar under a CLI/PTY thread on mobile had no spell check. Typos went
straight through to the agent unflagged, and the phone keyboard offered no help.

## The cause

The input carried all four "leave my text alone" attributes as a single gesture:

```jsx
autoCapitalize="off" autoCorrect="off" autoComplete="off" spellCheck={false}
```

That is the right cluster for a **shell prompt**. It is the wrong cluster for this
bar, which is a *message composer* that happens to sit under an xterm. Almost
everything typed into it is English prose aimed at the agent — control sequences go
through the soft-key row, and slash commands go through the `/` sheet, neither of
which touches this field.

The three attributes are three separate subsystems, and treating them as one setting
is what caused the over-correction:

| Attribute | What it actually controls |
| --- | --- |
| `spellcheck` | the red underline under a misspelled word |
| `autocorrect` | silently rewriting a misspelled word as you type |
| `autocapitalize` | uppercasing the first letter of a sentence |

## The fix

```jsx
autoCapitalize="off" autoCorrect="on" autoComplete="off" spellCheck
```

- **`spellCheck` on** — the requested behaviour: misspellings get flagged.
- **`autoCorrect` on** — on iOS the two are coupled in practice. With `autocorrect`
  off, the keyboard's correction machinery is disabled and older iOS suppresses the
  underlines along with it, so `spellcheck` alone would have been a no-op on the
  device that reported this.
- **`autoCapitalize` stays off** — this is the one that would genuinely hurt. Turning
  it on would send `Git status` and `Rg -n` into the PTY.
- **`autoComplete` stays off** — unrelated to spelling; it governs browser
  form-autofill, which has no business offering saved values here.

The slash-command search field keeps all four off. It matches command names, where
spelling help is only noise.

## Activating this

**Web-only** — a browser refresh is enough. No daemon rebuild, no restart.

One test covers it (spellcheck and autocorrect on, autocapitalize off), verified by
mutation: reverting the attributes fails it.
