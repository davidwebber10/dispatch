# Dispatch v3.8.0: security hardening (thread reports as data, file and size limits)

Agents still run with your rights and approvals off, by design. This release adds no approval
prompt, no permission mode and no per-tool confirmation.

## The change

- **Thread reports are data, not instructions (SEC-07, SEC-25).** A thread's report reaches
  Chat inside a marked block that the report text cannot close or forge. Overseer notices and
  dependent-thread tasks carry the worker's words the same way.
- **Report-started Chat turns get fewer tools.** When a report (not you) starts a Chat turn,
  that turn has no shell, no file writes, no web fetch, no connectors (Gmail, Drive, Calendar,
  Shopify and others), and no `SendMessage`, `ListAgents`, `RemoteTrigger` or `Workflow`.
  It keeps the Dispatch thread, memory and ledger tools (including `spawn_agent` and
  `message_thread`) and file reads. If it needs more, it says so and waits for your next
  message. A turn you start has every tool, as before.
- **A report never joins your turn.** A report that arrives while Chat is answering you is
  handled right after, in its own turn.
- **Links can't escape a project (SEC-12).** File routes check the real path. Links that stay
  inside the project, and pnpm `node_modules` links, keep working. Add other folders with
  `DISPATCH_FILE_ROOTS`. The "View file" absolute-path read is unchanged.
- **Size and rate limits (SEC-23)**, all adjustable by environment variable at daemon start:

  | Limit | Default | Setting |
  | --- | --- | --- |
  | JSON body | 1 MiB (50 MiB on image, hook and editor routes) | `DISPATCH_MAX_JSON_BYTES`, `DISPATCH_MAX_LARGE_JSON_BYTES` |
  | WebSocket message | 1 MiB; 8 MiB on the terminal | `DISPATCH_WS_MAX_PAYLOAD`, `DISPATCH_WS_TERMINAL_MAX_PAYLOAD` |
  | Running threads per project | 60 (0 = no cap) | `DISPATCH_MAX_LIVE_THREADS` |
  | Shortest schedule gap | 1 minute (0 = off) | `DISPATCH_MIN_SCHEDULE_MINUTES` |

- **Pasted secrets (SEC-17).** With Doppler connected, an integration refuses a typed-in token
  for a secret-looking header or env name and asks for a `${NAME}` reference. Stored
  integrations are untouched.
- **Smaller items.** `mcp-remote` pinned to 0.14.3 (SEC-16); CI token read-only and actions
  pinned to SHAs, unused `daemon/build` app removed (SEC-28); the `skipPermissions` request
  field is ignored (SEC-06); README states approvals-off by design and how telemetry works
  (SEC-06, SEC-27).

## Known items

- The pending-question JSON in `read_thread` is still raw; stored Chat lines made before this
  release carry no data note; older overseer notices print the raw agent label.
- Still open from the security review: SEC-04 (Doppler token), SEC-05 stage 2 keys, SEC-20,
  SEC-21, SEC-22.

## Under the hood

## Updating

Needs a daemon rebuild and restart. Run `dispatch update` (or `./bin/dispatch update` from
the repository folder), then reload the app.
