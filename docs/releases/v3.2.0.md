# Dispatch v3.2.0: see delegated work from Chat

## The change

Chat now shows the work it hands off to threads, live, without leaving Chat.

- **Live project pane.** The right pane lists each project's recent threads: name, state,
  harness, who started it (Chat, Overseer, You, a role, or another thread), start time and
  latest step. Threads that are waiting for you come first, with their question. Threads that
  finished today fold under "Done today (N)". The pane refreshes when a thread starts, stops
  or starts waiting, and again when the app comes back into view.
- **Started card.** When Chat starts a thread, a one-line "Started" card appears in the chat
  right away, with a live state mark. Tap it to open the thread.
- **Open threads in place.** A pane row, a Started card or a report card opens the thread in
  the same viewer the Overseer uses, over Chat. An "Open in Threads" button takes you to the
  Threads view if you want the full screen.
- **Doc links.** Paths to `.md` and `.txt` docs in replies, reports and Started cards become
  chips. A chip opens a read-only doc viewer that finds the right copy (the main checkout, a
  worktree or an unmerged branch) and says which copy you are reading. Copy path works
  everywhere; Reveal in Finder and Open in editor show only on the Mac itself.
- **Docs (N) per project.** Each project in the pane lists its in-progress docs only (not on
  main yet, or changed against main), at most 5. "+N more" opens the project in Threads. The
  list is hidden when there are none.

Known limits:
- Not yet tested in the iPhone home-screen app, or with a Started card from a real Chat turn.
- Reveal in Finder and Open in editor were not clicked in a real session.
- Doc reads stay inside the project folder, but a process running as you that swaps folders
  with exact timing could still read a file outside it. This adds nothing to the open-port
  issue tracked in #94, and is handled with it.
- Minor follow-ups from review are listed on PR #95.

## Under the hood

- Doc lookups run git asynchronously with `--no-optional-locks`, with a concurrency limit and
  a deadline, so they never block the daemon or a thread's own commit.
- Doc reads open the file without following links and check it is the same file that was
  checked.
- Started cards pair with their thread by tool-call ID, so a report that arrives in between
  does not strand them.

## Updating

Daemon and web app. Run `dispatch update`, then fully close and reopen the app (or reload the
page).
