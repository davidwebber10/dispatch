# Dispatch v2.35.0 — Fable review gates + coordinator ground rules

Driven by a usage analysis of ~131MB of live coordinator transcripts and the daemon
DB (see `docs/superpowers/plans/2026-09-02-overseer-tuning.md`).

## Fable review gates (PR #35)

Two new agent types, defaulting to the **fable** model tier:

- **design-reviewer** — gates a plan/design doc BEFORE implementation starts.
- **code-reviewer** — gates a finished diff AFTER implementation + self-review.

The coordinator prompt teaches both gates with explicit SKIP criteria (docs-only,
tiny diffs, chores, hotfixes, non-code work) so the expensive tier never runs on
trivial spawns, and a fence clause forbids downgrading a gate's model.

## Orchestration tuning (PR #36)

- The coordinator now knows `queue_agent`/`start_agent` (`dependsOn` chaining) —
  with the guardrail that an implementer is never pre-queued behind a design
  review (a queued stage auto-starts on ANY verdict).
- MODEL ECONOMY: concrete sonnet/haiku downgrade triggers (status checks, quick
  verifications, memory writes, git chores) + suggest scheduled runs for
  recurring nightly checks.
- Read-once discipline (no read_agent re-reads of an unchanged agent) and
  initiative-level mission naming.

## Daemon-enforced coordinator ground rules (PR #37)

Long sessions drift — coordinators start delegating and end up doing the work
themselves (observed: 587 direct Bash calls, including production deploys).
Prompt text decays with context; enforcement does not:

- New pure `coordinatorToolPolicy`, consulted by the structured membrane on every
  coordinator tool call. Denied: repo file writes outside `~/.claude/`,
  ship-shaped Bash (`git commit/push/merge/…`, `gh pr merge/create`,
  `gh workflow run`, `gh release`, publish, `dispatch update/release`,
  `terraform apply` — flag-tolerant, so `git -C ../wt commit` is caught), and
  native subagents. Every deny message names the delegation to do instead.
- Read-only inspection and the coordinator's own memory writes stay allowed.
  AskUserQuestion can never be policy-denied; worker agents are untouched.
- The prompt states the same rule (replacing the old dead-letter absolute ban)
  plus an anti-drift closing bullet.

## Updating

`dispatch update` restarts the daemon; every coordinator (existing or new) picks
up the new prompt, model wiring, and policy on its next process respawn — the
conversation history is preserved (sessions resume by id; the system prompt is
injected fresh at every process launch). No reset is required. The web rail
additions (type icons/labels) need only a browser refresh.

(PR #38 is the completion PR for the #36/#37 stacked-merge race; content is
identical to the reviewed stack.)
