# Dispatch v3.10.3: security cleanup, and CLI and Codex threads that wake and send

## Security

- **Push only goes to real push services.** Phone push sign-ups are accepted only for Apple,
  Google, Mozilla and Microsoft push hosts. Any other address is refused.
- **You can see who added things.** Integrations, schedules and roles now record who added
  them: you in the browser, or the thread by name. Settings and the Agents page show
  "Added by" and "Created by".
- **What threads may do.** A thread may add integrations and schedules and turn roles on.
  Editing, deleting, importing and exporting them, running a role, the shell and Chat stay
  yours only.
- **Two more path leaks closed.** The oversized-document error and the OpenRouter error no
  longer show paths or raw network messages.
- Removed a stray `terminals.ts-E` file that slipped into v3.10.2.

## Thread fixes

- **CLI threads wake their parent.** A parent thread now wakes when a CLI-mode child finishes.
  Before, it never woke.
- **Codex CLI threads get one-line messages.** A short message typed to a Codex CLI thread is
  now sent. Before, it could sit unsent.
- **A failed turn ends the turn.** When Claude Code stops on an error, the thread no longer
  stays stuck on "working".
- A thread's key is now revoked after the thread stops, and a restarted Codex thread no longer
  holds an old process id.

## Under the hood

- PR #117 (security) and PR #118 (thread fixes). Codex reviewed both.
- Tested on a spare copy with Grok, Codex and CLI threads. A signed-in Claude CLI wake and the
  Grok CLI were not tested live.

## Updating

Run `dispatch update` (or `./bin/dispatch update` from the repository folder), then reload the
app on each phone. This release adds a database migration (013), which runs on restart.
