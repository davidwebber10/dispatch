# Dispatch v2.41.1 — the dispatch command works from a symlinked folder

The `dispatch` command now runs when the checkout is in a folder with a symlink in its path.
(PR #54.)

## What was wrong

- **Every command did nothing, with no error.** From a checkout under a symlinked folder, for
  example `/tmp` on macOS (a link to `/private/tmp`), `dispatch release`, `dispatch status`, and
  every other command exited with code 0 and printed nothing.
- **Why.** The CLI starts only when Node runs its own file. It compared the path in
  `process.argv[1]` with the path of the module. Node resolves symlinks in the module path but
  not in `argv[1]`, so the two paths were different and the CLI did not start.

## The change

- The CLI now compares the real paths of the two files, so a symlink anywhere in the path does
  not matter.
- A symlink to `bin/dispatch` on your `PATH` worked before and still works.

## Under the hood

- New tests use a real symlinked folder. They check the direct path, a path through the
  symlink, a different file, and a missing path.
- The daemon's entry points use a different check and did not have this problem.

## Updating

Run `dispatch update`. It rebuilds the CLI. The daemon and the web app did not change.
