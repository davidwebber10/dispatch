# Dispatch v2.38.0 — Control Plane agent selector (Phase 1)

The Control Plane is no longer hard-locked to Claude workers. (PR #46.)

## New

- **Inline setup card.** A Control Plane with no session shows a setup card in
  place of the greeting: pick the default worker harness (Claude Code, Codex,
  Grok, OpenCode) and the coordinator's model. Start — or just type the first
  directive — creates the session with the shown selection. An existing
  session never shows the card; "New session…" flows into it naturally.
- **Worker harness choice.** `spawn_agent` / `queue_agent` accept an optional
  `harness` argument; otherwise the daemon resolves: per-agent-type worker
  matrix → session default → claude-code. The matrix
  (`PUT /api/settings/harnesses/overseer-workers`) is plumbing-only in this
  release — no UI yet.
- **Real availability guard.** Spawning a worker on a harness whose CLI is
  missing or signed out fails with a structured error instead of creating a
  dead thread (OpenCode is exempt from the sign-in check — the daemon injects
  its key).

## Safety

- Claude tier aliases (`sonnet`/`opus`/`fable`) can no longer reach a
  non-Claude CLI by any path: per-type tiers, explicit model args, matrix
  entries, or harness default settings.
- The coordinator itself stays on Claude in Phase 1. Phase 2 (non-Claude
  coordinators, Codex first) is specced in
  `docs/superpowers/specs/2026-09-22-control-plane-agent-selector-design.md`.

## Updating

Daemon + web. `dispatch update` (its restart applies the daemon side), then
reload the PWA / browser tab. The updated `spawn_agent` requires the updated
daemon — the normal update flow satisfies this.
