# Dispatch v4.6.3 — send a secret to a thread through the Inbox

## The change

- **Send a secret** in the Inbox: give it a name, paste the value, and Dispatch gives you a short
  ID such as `K7Q2M4`. Paste only the ID into the chat: "The secret "Stripe key" is in my Inbox:
  K7Q2M4". The value never goes into the transcript.
- **The thread puts the value where it is needed.** It calls the new `inbox_secret` tool with the ID.
  The daemon then writes the value to a file in the project (for example `STRIPE_KEY=…` in
  `.env.local`, file mode 0600) or to Doppler. The thread uses it by reference and does not see it.
- **One use, then gone.** After the first use, Dispatch deletes the value. The Inbox card shows which
  thread used it, when, and where it went. A secret that nobody uses expires after 24 hours.
- **Let the thread read it** (off by default) lets the thread read the value itself. The value then
  goes into the transcript.
- **Threads ask the right way.** Threads are told never to ask you to paste a key into the chat, but
  to use Inbox → Send a secret.

## Safety

- A secret sent from a thread works only for that thread. One sent from a project works for that
  project's threads.
- A thread cannot tell whether an ID belongs to another project. After 10 wrong IDs in 10 minutes,
  the thread must wait.
- The value is a private file in the daemon's data folder. No file route can serve it, and it is
  never in a list, a log or an alert.

## Updating

Needs a daemon rebuild and restart: run `dispatch update`, then reload the app. A thread gets the
`inbox_secret` tool when it starts or restarts.
