# Dispatch v2.36.3 — Uploads survive long daemon uptime

Fixes the bug where every upload ("Upload failed", instantly) broke in
threads, the control plane, and the Files pane after the daemon ran for a few
days. (PR #45.)

## The cause

multer created the upload temp dir `/tmp/commandcenter-uploads` once, at
daemon startup. macOS purges `/tmp` entries idle for ~3 days, so on a
long-running daemon the directory vanished mid-uptime and every upload then
failed with `ENOENT` until a restart. Frequent `dispatch update` restarts used
to mask this; a 6-day stretch without one exposed it.

## The fix

Both upload routes now recreate the temp directory on every request via a
`multer.diskStorage` destination callback. Daemon uptime no longer matters.

## Updating

Daemon-side. `dispatch update` (the restart it performs is what picks up the
fix). No session respawn needed.
