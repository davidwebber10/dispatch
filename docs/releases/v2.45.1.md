# Dispatch v2.45.1 — the test suite stays out of your home folder

The core test suite no longer writes into the home folder of the person who runs it, and it
can no longer start the real agent CLIs. Test data and tests use generic names. (PR #66.)

This release changes tests only. The daemon and the web app behave the same as in v2.45.0.

## The change

- Each core test file now runs with its own temporary home folder. A global setup makes one
  run folder in the OS temp folder and removes it when the run ends.
- Stub `claude` and `codex` programs come first on the PATH during the tests. They exit with
  code 127, so no test can start the real CLIs or reach an account.
- A guard test fails if the home folder or the stubs stop working.
- Test fixtures and test paths use generic plugin, server and user names.

## What was wrong

A full core test run wrote into the real home folder:

- `~/.dispatch/thread-<id>.mcp.json` files and `~/.dispatch/push.json`, from the app that the
  route tests create;
- `~/.claude.json` and Claude caches, because two terminal tests started the real `claude -p`.

Earlier runs left thousands of orphan `thread-*.mcp.json` files in `~/.dispatch`. This release
stops new ones. It does not remove old ones.

## Updating

Run `dispatch update`. No restart of overseers or threads is needed for this change.
