Control Plane Analytics

Two layouts for adding Control Plane metrics to the Analytics screen, drawn as the eight frames in the brief. Every frame is live: hover bars for tooltips, scroll inside a frame, and use the switch or the section bar.

Frame size
Recommendation

Ship Variant 1, the view switch

  • Where am I: the switch sits beside the title and always shows the current view. In Variant 2 the answer depends on scroll position, and near the boundary both sections are on screen at once.
  • Nothing jumps: title, switch, filters, and the KPI row sit at the same pixels in both views. Only the tile contents change.
  • Same screen: both views use one grammar: six tiles, then chart blocks, then tables.
  • Mobile: Variant 2 puts the Control Plane content about 5 screens down. Variant 1 reaches it in one tap.
Where Variant 2 is better

One scroll, no hidden state

  • You can compare usage and Control Plane numbers without switching views.
  • No stored view, so the first visit and the tenth look the same.
  • It needs a sticky filter row on desktop to keep filters reading as shared. That costs about 90 px of height on every scroll position.

Before this ships

Issues in the brief

  1. PW Explorer (OS) completed 8 missions but started 4. Completed seems to count missions started before the range. Either label the columns "started in range" and "completed in range", or the row reads as a bug.
  2. The Missions table is not scoped to the range. Its agent counts add up to 570, more than the 437 agents started in range, and two missions run 41 and 44 days. Scope it to the filters or label it "all time".
  3. Sessions: 15 in the tile, 5 in the By Project table. Each project row has 1 session. One of the two numbers counts something different.
  4. Two token totals under the same filters. Usage says 9.5B total tokens; the Control Plane tile says "1.6B of 6.1B". The caption should name the 6.1B (for example, "of tokens in Control Plane projects"). The brief also mixes 1.6B and 1.65B for the same number.
  5. Messages average 23 per day only on active days. 471 over 30 days is 16 per day; 23 is 471 over the 20 active days. The tooltip or caption should say which.
  6. Five colors cover three families of series (agent types, Control Plane vs agents, and message direction). I kept Control Plane amber and agents blue in both charts where they appear, but blue also means implementer. A reader may link the two.
  7. The Usage chart still breaks the new 5-series rule. The brief doesn't say whether to fix it. I folded it to the top 4 models plus Other (10 models) so the two views follow the same rules.
  8. The current charts skip empty days on the x-axis. The brief asks for one column per day, so I used a continuous 30-day axis in both views.
  9. Mobile tabs other than Usage are not specified. I drew Threads, Analytics, and Settings. For Variant 2 I also renamed the tab to Analytics, because the pane now holds more than usage.
