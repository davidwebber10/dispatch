# Coach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bundled Prompt coach with Coach: a tunable, private AI-upskilling plugin that watches how a person works, proposes one small next step on their weakest of five measures, learns from their feedback, and shows and bounds its own cost.

**Architecture:** Part A adds core capabilities every plugin can use: model calls that choose harness and model, richer metering with a time-filtered read and a limit-share estimate, a daemon-enforced budget, worker permissions for usage and analytics, plugin push, and SDK actions that open the schedule and new-thread dialogs pre-filled. Part B builds the `coach` bundled plugin on top: a worker runs pure detector functions over thread events and analytics, a judge pipeline picks models by thoroughness and budget, and the web part renders the card, the right-column tab, the Coach screen, the recap and the settings.

**Tech Stack:** packages/core (Express, better-sqlite3, vitest), packages/web (React 18, zustand, vitest + Testing Library), packages/plugins/coach (plain ESM JS like the other bundled plugins; worker as `.mjs`), packages/sdk (types).

**Spec:** `docs/superpowers/specs/2026-11-07-coach-design.md` (sections cited as §n).

## Global Constraints

- Each person's Coach data stays private to the daemon's owner; no team or manager reporting (§2, §9a.1).
- Never use the last of a limit: never take the last 10% of a 5-hour window (§9a.2); the budget is a hard stop (§4.5, §7.4).
- One budget number: "up to N% of the weekly limit" (default 3%) on the account the Coach uses; OpenRouter budget is dollars per week (§9a.2).
- Thoroughness: Economy · Balanced (default) · Thorough · Use my budget (§5).
- How often: Off · Quiet · Normal (≤ 3 cards a day) · Chatty (≤ 8); most per session default 1 (§4.3).
- ✕ means only "not now"; it never creates a fact or a negative weight beyond a rest (§4.1, §4.4).
- Every behavior has a setting with a default; thresholds and per-tier models live under Advanced (§2).
- Memory facts never hold prompt content; the card history may keep a short excerpt, removed by Reset (§9a.7).
- "Try it" never sends anything by itself (§4.1).
- Plugin id `coach`, name "Coach", bundled, off by default unless `prompt-coach` was on (§9, §9a.6).
- US spelling; card copy: headline ≤ 8 words verb first, one why line, no "should", no jargon for business users (§4.1).

## Review Focus

1. A budget reached mid-call or by concurrent calls: the cap must hold under 3 parallel assist calls — Task 4 test "three concurrent calls at 2.9% of a 3% cap: at most the calls already in flight finish; the next is refused".
2. A limit summary that is missing or stale (no Claude login, Codex poll gap after restart): `auto` must not crash or pick a dead account — Task 3 test "auto with no usage summary falls back to the first signed-in harness and says why".
3. A person who mutes, then the recap job fires: no card and no push during a mute or quiet hours — Task 10 test "mayShow is false during a mute and in quiet hours, for the recap too".
4. Thread events for a project on the leave-alone list, or a thread of another plugin's agent (`source !== 'user'`): no detection — Task 8 test "events from a left-alone project or a non-user source produce no candidate".
5. A large model that returns malformed JSON or nothing: the card must not show half-filled — Task 9 test "a malformed or empty answer drops the candidate and records the call".
